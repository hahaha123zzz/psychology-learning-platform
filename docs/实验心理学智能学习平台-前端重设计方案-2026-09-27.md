# 实验心理学智能学习平台：教师端 + 学生端前端重设计方案

> 版本：2026-09-27  
> 核心约束：**未实现的功能不制作前端入口、不做灰色假按钮、不用静态假数据伪装能力。**

## 1. 重设计目标

本次前端重设计不以“展示 AI 技术”为目标，而以两类用户的真实任务为中心：

```text
教师端
= 管理课程
→ 管理教材
→ 管理题目/测验
→ 查看班级学情
```

```text
学生端
= 继续学习
→ 阅读教材
→ 遇到问题获得有据解释
→ 完成测验/复习
→ 查看自己的学习进展
```

产品整体应该让用户感受到：

> 这是一个课程学习平台，而不是把 RAG、Agent、Embedding、Celery 等工程能力直接暴露给用户的控制台。

---

# 2. 开源项目借鉴

本方案主要借鉴：

- Open edX：教师创作环境和学生学习环境明确分离。
- Canvas LMS：稳定的课程上下文和课程级导航。
- Dify：文档列表、状态、处理进度与复杂能力分层。
- Langflow：其工作流画布适合开发者，但不适合普通教师和学生，因此明确不照搬。

参考项目：

- https://github.com/openedx/frontend-app-authoring
- https://github.com/openedx/frontend-app-learning
- https://github.com/openedx/frontend-app-learner-dashboard
- https://github.com/instructure/canvas-lms
- https://github.com/langgenius/dify
- https://github.com/langflow-ai/langflow

# 3. 统一设计原则

## 3.1 教师端和学生端共用视觉语言，但不共用信息架构

统一：

- 顶部课程身份
- 字体与间距体系
- 卡片样式
- 状态颜色
- 表格
- Dialog / Drawer / Toast
- 空状态和失败状态

但：

```text
教师端 = 管理教学
学生端 = 完成学习
```

不能只是同一套页面换权限。

## 3.2 前端只说用户语言

不直接暴露：

```text
KnowledgeObject
RetrievalUnit
RRF
Dense / Sparse
Embedding
Celery
Worker
Checkpoint
PublicationSnapshot
MinIO
bbox
```

普通用户只看到：

```text
教材正在解析
教材存在问题
索引正在准备
教材已发布
```

## 3.3 每个状态只突出一个主要动作

例如教材存在阻塞问题：

```text
[查看问题]
```

不要同时出现大量不相关按钮。

## 3.4 未实现功能完全不出现

当前不做前端入口：

- OCR 模式
- 扫描 PDF 智能识别
- MinerU / Docling 切换
- 视觉检索
- ColPali / ColQwen
- 多向量检索
- 复杂表格智能分析
- 可靠公式 LaTeX
- 图片视觉问答
- AI 自动修复教材
- 教师手动 bbox 编辑器
- 教师人工段落拆分/合并编辑器
- 图文关系编辑器
- Parser 参数
- Embedding 参数
- RRF 调参入口

特别说明：

当前系统即使能够发现某些机器无法解决的教材问题，教师目前也没有完整人工修复闭环。

因此前端只允许：

```text
展示问题
说明影响
展示当前真实可执行动作
```

不能伪造“手动修复”页面。

# 32. 状态视觉规范

统一使用：

```text
灰色：草稿 / 尚未开始
蓝色：进行中
黄色：需要关注
红色：失败 / 阻塞
绿色：完成 / 已发布
```

不要给每个后端状态单独设计颜色。

---

# 33. 整体视觉风格

推荐：

- 浅色学术型界面
- 白色 / 浅灰为主
- 清晰文字层级
- 少量主色强调
- 不使用大面积 AI 渐变
- 不使用霓虹科技风
- 卡片数量适度
- 中等偏高信息密度
- 教材正文优先保证阅读体验

整体更接近：

```text
现代 LMS + 知识工作台
```

而不是：

```text
AI Demo + 科技大屏
```

# 39. 第一轮验收标准

## 教师端

- 进入课程后能快速知道当前待处理事项。
- 一眼理解每本教材当前阶段。
- 不需要理解 Celery、RAG、Embedding。
- 未实现功能完全不可见。
- 系统无法解决的问题明确说明问题、影响和当前真实动作。
- 不制造教师无法操作的假修复页面。

## 学生端

- 进入课程后立即知道下一步学习动作。
- 教材正文而不是聊天框成为视觉中心。
- AI 回答明确绑定教材证据。
- 测验与复习统一为“练习”。
- 掌握度与学习证据集中在“成长”。
- 不展示教师工作台、后台任务和未发布资源。

# 40. 最终产品心智

教师：

```text
我在管理一门课程。
```

学生：

```text
我在完成一门课程的学习。
```

而不是：

```text
我在操作一个 AI / RAG 系统。
```

这应成为本次前端重设计的最高原则。
