# 实验心理学智能学习平台：项目当前状态

> 更新时间：2026-09-26  
> 项目阶段：V2 本地业务闭环已完成；V3 真实开放教材评测与技术选型进行中。  
> 当前不纳入范围：生产部署、监控告警、备份恢复、容量验证和真实班级试用。

## 1. 项目定位

本项目是面向《实验心理学》课程的 B/S 智能学习平台，目标是形成以下闭环：

```text
教师发布可信课程资料
→ 系统解析教材并构建知识与检索索引
→ 学生围绕教材阅读、提问、练习和复习
→ 系统保存引用证据、掌握状态与复习任务
→ 教师依据聚合学情调整教学
```

核心原则：

- AI 回答必须基于课程教材；证据不足时拒答或降级。
- 教材、题目、学生答案、评分和学习证据均需要绑定不可变版本。
- 教材需经过教师审核、索引构建和发布门禁后，学生才能使用。
- 前端仅展示角色真实可用的功能，后端 RBAC 是最终权限边界。

## 4. 教材与资料管理

### 4.1 上传与存储

当前上传链路（V3.2 可恢复分片上传）：

```text
浏览器创建上传会话（upload_sessions）
→ 服务端预校验（扩展名、大小、配额、重复）
→ 按分片请求 MinIO 预签名 URL，浏览器直传 MinIO
→ 服务端记录各分片 ETag 与大小
→ complete：服务端合并 Multipart、流式校验大小与 SHA-256
→ PostgreSQL 保存资料、版本和元数据
```

已实现：

- 教师端主要支持 PDF、DOCX 上传。
- 校验扩展名、文件签名、空文件、大小、课程配额和重复文件。
- 支持 `Idempotency-Key`，防止重复提交。
- 单文件默认上限 200MB；单课程默认总配额 20GB。
- 原教材二进制只存 MinIO，不存入数据库。
- 数据库保存文件名、大小、SHA-256、MIME 类型、MinIO 对象键、资料版本与状态等元数据。
- V3.2：分片直传、ETag 校验、会话取消与过期清理；浏览器本地记录会话，重进页面可恢复未完成上传，显示真实分片进度与离页告警。

典型对象存储键：

```text
courses/{course_id}/uploads/{upload_session_id}/source.pdf（合并后转为不可变版本键）
courses/{course_id}/materials/{material_id}/versions/{version_id}/source/source.pdf
```

当前限制：

- 前端暂无“暂停”按钮与分片级重试控件（重进页面可整体恢复）。
- 后端已有错误码、详细信息和 `retryable` 字段，前端尚未完整展示可操作诊断信息。

### 4.2 教材版本、解析与发布门禁

关键状态：

```text
uploading → uploaded → parsing → parsed
                         ↘ failed
parsed → 索引就绪 → published
```

学生能使用教材的完整条件：

```text
学生已加入课程
+ 教材处于 published
+ 当前版本解析成功
+ 阻塞性质量问题已处理
+ 当前 Embedding 版本的索引已构建完成
= 学生可见、可阅读、可检索和可问答
```

因此，“教师端发布了但学生看不到”通常由成员关系、资料草稿状态、解析失败、质量门禁或索引未完成造成。

### 4.3 PDF 与 DOCX 解析

#### PDF

- 使用 `pypdf` 提取原生文本。
- 使用 PyMuPDF 提取原生文本块和段落 bbox。
- 段落可关联页码、章节、原始文本和 bbox。
- 单页提取异常会尽量跳过，不必然导致全书失败。
- 本地已验证 OpenStax《Psychology 2e》的原生文本段落 bbox 可用。

#### DOCX

- 使用 OOXML 结构解析。
- 可提取标题、段落、表格、图片、公式等对象。
- Word 不具稳定固定分页版面，因此不伪造页内 bbox。
- 会产生 `layout_bbox_unavailable` 等质量提示。

#### 当前解析限制

- 未接入 OCR，扫描版 PDF 解析质量有限。
- 未接入 MinerU、Docling 等完整版面恢复工具。
- 尚没有可靠的图片、表格、公式 bbox 对象主链路。
- 尚未实现视觉检索。
- 解析/索引任务已改为持久任务派发（V3.2）：默认由本地 Celery Worker 执行（`scripts/dev.ps1` 受管启动），`jobs` 记录心跳、尝试次数、检查点与执行后端；`scripts/requeue_stale_jobs.py` 可扫描并安全重派发心跳超时的陈旧任务。
- 服务重启后，进行中的任务依赖陈旧任务扫描重派发恢复，尚无自动守护与告警。
- 暂无页级检查点细粒度续跑；解析阶段大教材仍整体读入内存。

## 5. 知识对象、检索单元与 RAG

### 5.1 当前知识模型

V3 已建立：

```text
KnowledgeObject
Representation
Relationship
RetrievalUnit
```

- `KnowledgeObject`：章节、段落、图片、表格、公式等教材语义对象。
- `Representation`：对象的文本、图像或结构化表达。
- `Relationship`：章节包含、段落相邻、图文关联等关系。
- `RetrievalUnit`：实际进入索引的最小检索单元。

现已稳定实现文本 Chunk 与来源对象、`RetrievalUnit → KnowledgeObject` 的映射，并支持回溯父对象和相邻上下文。

基本原则：

```text
Retrieval Chunk ≠ Generation Chunk
```

检索可用小 Chunk；生成回答时需要回溯到父段落、相邻段落或章节，不能把单一命中的片段直接当作完整教材证据。

### 5.2 当前检索技术

```text
BM25 稀疏检索
+ pgvector 向量检索
+ RRF / Weighted RRF 融合
+ 权限、章节和对象类型前置过滤
+ 自适应 Top-K 截断
+ 低置信度拒答
```

已实现：

- OpenAI-compatible Embedding 适配器。
- 未配置外部 API 时，使用本地确定性 `hash-v1` 测试替身。
- `hash-v1` 仅作为关键词锚点基线，不伪装为真正语义向量。
- 向量结果受最小相似度门槛限制，低相似结果不能作为教材证据。
- 查询分析会给文本和视觉通道提供先验；视觉通道目前只返回明确降级提示。
- 章节和对象类型过滤发生在候选检索和排序之前。

### 5.3 当前 RAG 评测结果

语料：OpenStax《Psychology 2e》，仅允许本地离线解析与检索对照，禁止发送给外部 Embedding 或生成式 AI 服务。

`hybrid-v4 + hash-v1` 本地基线：

| 指标 | 结果 |
| --- | --- |
| 页级 Recall@5 | 1.0 |
| Page NDCG@5 | 0.826186 |
| 教材外问题拒答准确率 | 1.0 |
| 精确对象 Recall@5 | 0.625 |
| 首项 bbox IoU | 0.480661 |

结论：文本检索和教材外拒答已有可用基线；图题仍主要命中图注文本，图片对象、视觉检索、表格/公式检索和精确视觉引用尚未完成。

## 7. 题库、测验与学习活动

已实现：

- 题库、题目审核与发布。
- 出题任务与候选题。
- 测验创建、发布、作答、自动评分与结果。
- 学生只可发现已发布测验。
- 草稿测验详情对学生返回 404。
- 未开放或已关闭测验不向学生下发题目内容。
- 题目、作答和评分依据绑定版本。

业务原则：AI 生成题目只是候选，不能自动成为正式题；模型输出不得直接改变学生评分、学习状态、权限或发布状态。

## 10. 当前教材发布工作台改造方向

目标流程：

```text
选择教材 → 上传 → 解析 → 教师审核 → 构建索引 → 发布给学生
```

第一阶段（在当前架构内）应完成：

- 显示上传、解析、审核、索引、发布的明确流程条。
- 每个任务显示阶段、进度、加载动画、成功/失败结果和耗时。
- 展示服务端错误码、错误详情、`retryable` 和下一步操作。
- 页面刷新或切换后，可从服务端任务状态恢复展示。
- 建立统一“后台任务”入口。
- 每个状态只突出一个主要按钮：上传、解析、审核、建索引或发布。
- 索引未就绪时禁用发布，并明确说明学生暂不可见的原因。

后续架构升级：

```text
MinIO 预签名分片上传
→ 上传会话与分片校验
→ 暂停、恢复、断点续传与单分片重试
→ 持久消息队列 Worker
→ 任务租约、心跳和失败恢复
→ 页级解析检查点
→ 服务重启后自动恢复或安全重试
→ 流式读取与内存控制
→ OCR、版面恢复与多模态对象解析
```

## 11. V3 当前目标与待选型技术

V3 的目标是通过开放教材进行可复现评测，而不是先做演示性多模态效果。

评测维度：

```text
解析质量、文本检索 Recall/NDCG、对象命中率、页码召回、bbox IoU、
教材外拒答、引用正确性、图表命中率、延迟、索引大小、内存/VRAM
```

待对比方向：

| 方向 | 候选 |
| --- | --- |
| 文本 Embedding | BGE-M3、多语种模型、供应商 API Embedding |
| 检索融合 | Dense、Sparse + Dense、RRF、Weighted RRF、Score Normalization、Learned Fusion |
| 视觉检索 | ColPali、ColQwen、VisRAG、CLIP 单向量、Multi-vector Late Interaction |

模型与供应商要求：

- 当前可通过配置切换单一 OpenAI-compatible 供应商。
- 数据库向量维度目前为 384，外部模型必须支持 `dimensions=384`。
- 切换 Embedding 模型或版本后必须重建索引。
- 教材发送给外部模型前，必须确认逐本许可、供应商不保留/不训练承诺及用户授权。
