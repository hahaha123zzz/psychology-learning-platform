# 课程导向前端重设计执行计划

## 前置约束

- 仅消费既有 API；如发现接口不能支撑页面，先将该功能留在旧页或不展示，不临时伪造数据。
- 保留用户未提交的 `web/next-env.d.ts`、`web/CLAUDE.md`、用户提供文档与本地测试语料。
- 每个阶段先完成角色访问和真实空/错/加载状态，再完成正常展示。

## P0：课程级框架

1. 梳理当前 `/me`、`/courses` 与现有角色守卫，提取课程选择与角色导航数据模型。
2. 建立教师/学生 CourseShell、课程列表路由及课程上下文加载组件。
3. 改造根导航和旧地址，使其只做合法默认课程跳转；消除同页混杂多角色入口。
4. 建立共用状态组件和设计令牌，避免继续扩张旧 `functional-*` 单页样式。
5. 验证教师、学生与管理员的访问跳转，验证空课程与加载失败。

## P1：教师教材工作流

1. 将现有真实上传、教材列表、流程、审核问题和任务列表拆到教材页/详情页/问题页。
2. 保留 `uploadMaterialResumable` 的恢复语义，改写为教师语言的上传面板。
3. 基于 workflow 的 `allowed_actions` 实现唯一下一步操作、流程步骤与状态徽章。
4. 把课程任务从主页面抽成教师专用 Drawer；持续任务只轮询真实 jobs。
5. 建立课程概览，只展示已有聚合统计、待处理教材和真实空状态。
6. 验证上传中离开/返回、解析失败、审核阻塞、索引、发布及学生可见性。

## P2：学生学习空间

1. 迁移学生课程首页，使用已发布资料、复习任务、开放测验和掌握度的真实结果。
2. 将检索、有据问答和引导学习会话整理进 `/learn`；教材优先，助手为辅助面板。
3. 将局部追问由单独一级入口迁入学习上下文，不改变其“确认后合并”语义。
4. 验证无已发布资料、证据不足拒答、SSE 生成中、课程切换及权限边界。

## P3：学生练习、成长、我的

1. 聚合已有测验与复习任务为练习页，保留服务端时间、保存和提交校验。
2. 建立成长页，只消费掌握度和复习数据。
3. 整理记忆摘要与隐私删除入口，不将原始内部 JSON 当作面向用户的常规内容。
4. 验证测验作答/断点保存/提交/结果与删除请求确认。

## P4：教师其余模块与收口

1. 迁移题库、测验、学情、成员到课程 Shell。
2. 移除已迁移的旧单页入口与过时技术文案；保留兼容跳转。
3. 补前端单元/路由测试与浏览器端冒烟；运行类型检查、lint、构建。
4. 对照设计规格逐项检查无静态假数据、无越权导航、无未实现入口。

## 提交与验证策略

每个 P 阶段独立提交。涉及公共路由执行 `pnpm typecheck`、受影响测试与构建；涉及样式/交互执行 Playwright 冒烟。任何 API 变化才导出 OpenAPI 并执行相应后端测试；本计划默认不改变 API。
