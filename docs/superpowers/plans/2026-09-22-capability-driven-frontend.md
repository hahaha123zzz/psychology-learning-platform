# 能力驱动前端收口计划

## 目标

以已提交的 OpenAPI 契约为唯一功能来源。前端只展示能通过现有后端完成的操作，不将视觉原型中的示例教材、虚构进度、伪造 bbox 或无服务端动作的按钮暴露给用户。

## 实施顺序

1. 增加 Next 同源 `/api/*` 代理和统一 API 客户端，保留服务端 HttpOnly Cookie 会话；增加登录页与未认证处理。
2. 替换教师原型页：课程选择/创建、真实资料清单、PDF/DOCX 上传、解析任务轮询、解析问题处理、索引构建、发布和课程聚合学情。
3. 替换学生原型页：只列已发布资料；提供教材检索与证据预览、课程问答 SSE、已发布测验、待复习任务、掌握度与记忆摘要。
4. 删除或不渲染没有接口支撑的页面控制项。视觉仅服务于以上真实状态，所有按钮展示加载、失败和权限提示。
5. 为 API 客户端和各页能力边界补充源代码契约测试；运行前端完整检查与后端 G0 冒烟。

## 明确不在本轮前端呈现的能力

- PDF/DOCX 页内精准 bbox 阅读器：PDF stub 无可验证 bbox，DOCX 会明确返回 `layout_bbox_unavailable`。
- 视觉检索、真实供应商模型配置、生产 Worker/可靠队列：均属于当前冻结或未生产化的 V3/运维范围。
- 未发布题目、草稿测验、学生私聊/记忆正文、管理员审计详情：前端不得用示例数据绕过权限或发布语义。

## 验收

- 登录后由 `/me` 的真实角色和课程成员关系决定可进入的工作区。
- 每个页面操作有一个现有 API 对应，失败信息采用服务端 `error.message`。
- 课程/资料/测验/问答数据都来自 API，不存在初始静态样例。
- 前端 `test`、`typecheck`、`lint` 通过；在服务运行时完成关键 API 的手动闭环验证。
