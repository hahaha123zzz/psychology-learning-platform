# V2 业务闭环收口与图稿驱动前端设计

## 1. 目标

当前阶段集中完成两件事：

1. 将 V2 后端从“主要模块已有代码”收口为可联调、可验证的完整业务闭环。
2. 通过“页面需求 → 生图提示词 → 用户提供 AI 图稿 → 图稿拆解 → 前端实现”的方式完成教师端和学生端。

V3 多模态 RAG 暂停新增功能，保留已完成的评测、对象模型、资产与 bbox 合同，不继续接入新解析器、视觉索引或真实模型。

## 2. 范围

### 2.1 V2 后端四条闭环

#### 教师资料链路

教师上传 PDF/Word，系统创建不可变版本与解析任务，教师查看质量问题、修正并发布，学生只能读取已发布且仍有权限的版本。

#### 学生学习链路

学生进入课程和章节，围绕已发布教材提问；系统完成检索、SSE 回答、证据引用、拒答与学习事件记录，并维持历史教材版本语义。

#### 练习复习链路

教师创建或审核题目并发布测验，学生作答、提交和查看反馈，系统生成错题与复习任务；题目、答案、评分规则和作答均绑定不可变版本。

#### 教师回看与平台安全链路

教师查看课程级学习统计与审核记录；平台提供依赖健康、权限隔离、审计、隐私删除和模型调用安全边界。

### 2.2 前端范围

第一阶段只设计并实现：

- 教师工作台：课程概览、教材发布、解析审核、题库/测验、班级学习回看。
- 学生学习空间：课程、教材阅读、AI 问答与证据侧栏、测验、错题与复习。

登录、角色入口、管理健康页及独立的通用状态页面暂不做视觉设计；现有必要入口和错误反馈仍需保持可用。

## 3. 执行顺序

1. 审计 V2 后端现有实现与契约，建立“已实现、缺测试、缺联调、缺实现”的事实矩阵。
2. 依次收口教师资料、学生学习、练习复习、教师回看与安全四条链路。
3. 每条链路后端稳定后，输出对应页面包的 AI 生图提示词。
4. 用户提供生成图后，将图稿冻结为视觉基线，并拆解组件、状态、接口字段、响应式和无障碍规则。
5. 按冻结图稿实现前端并完成接口联调。

## 4. 后端完成标准

一条链路只有同时满足以下条件才标记完成：

- API、状态机、版本与权限语义完整。
- 数据模型和 Alembic 迁移一致，不修改历史迁移。
- 成功、越权、非法状态、幂等/重复提交、并发冲突与失败恢复测试齐全。
- OpenAPI、事件契约和必要文档同步。
- Docker 可用时完成数据库迁移、依赖健康和端到端联调。

缺少 Docker、真实教材或真实模型证据时，只能声明代码与自动化测试完成，不能声明环境或真实数据验收完成。

## 5. 图稿与前端合同

每个页面提示词包包含：

- 目标角色、任务和使用场景。
- 桌面画幅、信息层级和主要区域。
- 必须出现的业务组件与真实状态。
- 视觉语言、颜色、排版、密度和可访问性约束。
- 禁止出现的虚构功能、装饰性图表和无法落地交互。
- 同一页面需要的默认、加载、空、错误、阻塞和成功状态。

AI 图稿只决定视觉层级与布局，不修改服务端权限、教材版本、审核、引用、拒答和审计规则。收到图稿后形成页面实现规格，再开始写 UI。

## 6. 测试与验收

- 后端：Ruff、Pytest、Alembic upgrade/check、OpenAPI 漂移、G0 冒烟和四条闭环集成测试。
- 前端：Node 测试、TypeScript、ESLint、构建和浏览器 E2E。
- 安全：身份、课程成员、资源状态和权限过滤均在服务端执行；越权资源统一避免可枚举响应。
- 真实验收：后续使用真实 PDF/Word 教材进行教师抽样审核，但不阻塞当前功能开发。

## 7. 暂不实施

- V3 新解析器、Visual Embedding、Multi-vector、Query-aware Fusion 和模型选型实验。
- 登录页、管理健康页和独立通用状态页的视觉重做。
- 生产部署、真实班级发布和未经用户确认图稿的前端视觉重构。
