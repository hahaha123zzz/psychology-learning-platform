# V3 开放教材评测语料设计

## 目的

用可公开获取、原生数字版的心理学教材验证 V3，不把单一示例文件或页面截图当作检索质量证据。评测优先回答四个问题：解析对象是否完整、文本检索能否召回正确教材位置、引用能否准确落到对象/页码、证据不足时能否拒答。

## 选型

首轮采用两类来源。

1. **主基准：KPU《Research Methods in Psychology, 4th Edition》**。其主题与《实验心理学》最接近，具有清晰章节层级、研究设计、统计与练习内容，适合文本检索、表格和定义题标注。
2. **泛化对照：OpenStax《Psychology 2e》**。其覆盖面、图表和章节规模适合验证跨章节检索与解析稳定性；但仅允许本地离线评测，禁止进入任何外部模型调用路径。

BCcampus、UNA、WSU 三本作为第二批泛化语料：只有首批的解析、标注和基线运行稳定后才下载并加入，避免尚未建立质量基线时把问题混在一起。

## 数据与边界

下载的 PDF 存在 `data/oer-textbooks/`，它已被 Git 忽略；仓库只保存来源 URL、许可、下载日期、SHA-256 和人工标注，不提交教材二进制。下载脚本只接受明确列出的官方地址，并要求 `--accept-licenses`，防止无意下载或误用。

所有语料默认是 `local_only`：可用于本地 PDF/DOCX 解析、哈希嵌入、BM25、pgvector 本地索引和人工审查。将内容发送到任何外部 Embedding 或生成 API 不是本阶段范围。OpenStax 的官方限制更严格：即使未来供应商承诺不训练，也继续保持本地对照，除非得到权利方单独书面许可。

## 评测流程

```text
官方 PDF → 下载清单（哈希）→ 本地解析 → 人工抽样标注
       → RetrievalUnit / GenerationUnit 切分候选
       → BM25、Dense、Hybrid/RRF 等候选运行
       → Recall@K、nDCG、页码/对象定位、引用精确率、拒答、延迟报告
```

`RetrievalUnit` 是用于排序和召回的最小对象/子块；`GenerationUnit` 是向回答器提供的、带相邻上下文的父段/对象集合。两者不得强制相同。当前阶段先使用现有对象合同和本地检索基线，不假称已有可靠 bbox、视觉嵌入或多向量索引。

## 验收顺序

1. 下载首批两本教材并记录哈希，确认 PDF 是可解析的数字文本。
2. 对每本抽样至少覆盖段落、章节标题、表格/图注和教材外问题，建立人工评测集；没有真实 bbox 时明确标记为 `unavailable`，不填写伪坐标。
3. 在固定评测集上运行现有 BM25/哈希 Dense/Hybrid 基线，输出可比较的运行结果。
4. 根据同一评测集比较后续文本 Embedding、视觉模型及 Query-aware Fusion；只有满足证据、成本和延迟门槛的候选才能进入产品实现。

不包含生产部署、外部 API 密钥配置、真实学生数据或自动发布。
