# V3.3：可验证 PDF 版面对象与页级恢复设计

## 1. 目标与范围

V3.3 在 V3.2 的可恢复上传和持久任务执行之上，面向**原生数字 PDF**建立可验证的版面对象管线。目标是让教材中的段落、嵌入图片，以及可保守识别的表格和公式，拥有真实的页码、统一坐标系中的 `bbox`、来源信息和可追溯资产；解析任务在页级失败或重派后可以从已持久化检查点继续。

本版本的完成条件是：

1. 解析结果中的对象坐标可用于现有阅读器的精确跳转和高亮，坐标统一为 PDF 用户空间 `[left, bottom, right, top]`。
2. 每页完成后写入稳定检查点；同一解析任务重试时跳过已成功持久化的页，不重复创建对象或资产。
3. 图片、表格、公式只在真实检测到时才创建对象；无法可靠识别时保留告警，不用段落或猜测结果伪装为对应对象。
4. 解析产物可供教师审核，且重新解析仍会使旧索引失效，必须重建索引后才能发布。
5. 在本地开放教材上产生可复现的对象数量、bbox 覆盖率、对象级检索及跳转抽样报告。

本版本不包括 OCR、MinerU、Docling、扫描件版面恢复、外部生成/嵌入 API、视觉模型、视觉检索、自动表格语义理解或公式 LaTeX 生成。这些能力只有在获得可评测样本与独立选型结论后再进入后续版本。

## 2. 方案选择

采用 PyMuPDF 原生数字 PDF 适配器，而不是立即接入重型文档智能框架。

- PyMuPDF 能从 PDF 原生对象取得文本块、图片块和坐标，数据来源明确，适合当前可验证目标。
- 对表格和公式采用保守候选策略：表格仅在页面的绘制线、规则网格和相邻文本布局同时支持时创建 `table`；公式仅对可从原生文本块和数学字符形态稳定识别的独立块创建 `formula`。其余情况产生审核告警。
- 不把图片对象自动当作视觉可检索对象。本版本只形成对象和裁剪资产，为后续被批准的视觉表示与模型评测提供输入。

## 3. 解析架构

新增 `NativePdfLayoutParser`，保留 `StubPdfParser` 名称作为现有调用方的兼容入口，解析器版本提升为 `native-layout-v3.3`。

解析分两层：

1. **页面提取层**：逐页打开 PDF，提取原生文本块、图片块、绘制路径和页面大小；将 PyMuPDF 顶部原点坐标转换为项目统一 PDF 用户空间坐标。
2. **对象归并层**：从页面布局生成 `chapter`、`paragraph`、`figure`、`table`、`formula` 对象。每个对象保留 `physical_page`、`reading_order`、`bbox`、置信度和解析器版本。图片对象保存其原始 PDF 图片或页面裁剪的不可变资产；图注、表题、相邻段落仅通过 `caption_of`、`references` 等关系关联，不能替代图片或表格对象本身。

章节识别延续已验证的 OpenStax 规则。对象排序以页面内垂直位置和横向位置为主，按页面累加为全书 `reading_order`。跨页对象不在本版本自动拼合：各页分别建对象，并以 `continues_on` 或审核告警表达不确定性。

## 4. 页级检查点与幂等持久化

解析 Job 的 `checkpoint` 扩展为：

```json
{
  "stage": "parse_pages",
  "parser_version": "native-layout-v3.3",
  "completed_pages": 42,
  "total_pages": 386,
  "last_page": 42,
  "object_count": 815,
  "asset_count": 31
}
```

解析首先下载源文件到 Worker 内存/临时打开句柄；不会将整本教材额外写入数据库。每成功处理一页，在同一数据库事务内写入该页对象、资产元数据、页完成标记和 Job 检查点。崩溃或 Worker 重派后，从最后成功页面后的下一页继续。

为避免重试重建重复对象，新增“版本 + 解析器版本 + 页面”的页级解析记录（或等价唯一约束）。对象和资产键由教材版本、解析器版本、页码、对象序号及内容 Hash 组成。重试若遇到已完成页，校验页记录后跳过；若页记录不完整，事务回滚后整页重做。

只有所有页成功后，任务才进入质量汇总并将教材版本置为 `parsed`。单页不可恢复错误会将 Job 标为失败、保留已完成页和检查点，并附上页码、错误码、是否可重试；重试继续未完成部分。重新发起一次明确的“重新解析”仍走现有全版本替换语义，清理旧对象、关系、资产、RetrievalUnit 和索引后重建，绝不覆盖已发布快照。

## 5. 对象、资产、关系和审核语义

现有 `KnowledgeObject`、`ObjectAsset`、`ObjectRelation` 和 `ParseReviewIssue` 为主数据模型，V3.3 增加页级持久状态，不扩展为视觉索引。

对象及最低要求：

| 类型 | 创建条件 | 内容/资产 | 失败处理 |
| --- | --- | --- | --- |
| `paragraph` | 原生文本块有效 | 规范化文本 + bbox | 无文本时页面告警 |
| `figure` | PDF 图片块或可裁剪的图形区域有效 | 原始图片或 PNG 裁剪资产 + bbox | 只创建告警，不用图注替代 |
| `table` | 有可信网格/布局候选 | 可读文本摘要 + bbox；无结构化表格承诺 | `table_detection_uncertain` 告警 |
| `formula` | 独立数学文本块符合保守规则 | 原文 + bbox | `formula_detection_uncertain` 告警 |

图注/表题关系仅当临近文本和编号模式共同支持时建立，关系来源写为解析器、状态为待审核；不确定时不连边。资产入 MinIO 的不可变版本路径，SHA-256、页码、bbox、尺寸和渲染版本写入 `ObjectAsset`。资产写入失败使该页失败，不能生成一个没有可用资产却声称可定位的图片对象。

质量问题分级：坐标缺失、页面提取失败和资产写入失败为 `blocking`；置信度不足、候选表/公式未确认、疑似跨页对象为 `warning`；统计性信息为 `info`。教师现有审核工作台只展示实际生成的对象和问题，不为未实现的视觉检索增加入口。

## 6. 索引与检索边界

V3.3 不改变 `paragraph-child` 的文本检索主路径。解析完成后，段落继续构建 `text_child` RetrievalUnit；图片、表格、公式对象暂不自动进入检索索引。

因此：

- 通过对象 ID/引用跳转可精确定位所有成功对象；
- `/knowledge/search` 请求图、表、公式过滤时，除非未来真正建成相应 Representation 与 RetrievalUnit，否则仍返回空结果；
- 不得将图片裁剪、图注或表格文本称为“视觉检索命中”；
- 后续版本可以基于已保存资产补建 `image`、`table`、`equation` RetrievalUnit，且不改动原始教材对象。

## 7. API、前端与权限

保持已有解析任务查询协议。任务详情新增或规范化页面进度、当前页、总页数、已建对象数、已建资产数、失败页及下一步操作；所有字段从 Job 检查点和实际数据库状态读取。

教师端在已有教材发布工作台中显示真实阶段“逐页解析”，用加载动画显示已完成页/总页数和对象数；解析失败时显示具体页码与可重试原因。仅教师可见本课程解析详情和审核项。学生只在发布快照存在、版本通过发布门禁后获得教材及可点击引用，不能看到草稿资产、解析告警或重试控件。

## 8. 验收与测试

1. 解析器单元测试：坐标变换、图片对象、保守表格/公式判定、无证据不建对象、图注关系。
2. 服务测试：第 N 页后故障、Job 重派、从 N+1 继续、同页重试幂等、资产写入失败、重新解析使索引失效。
3. 权限与 API 测试：无权用户 404、学生不可见草稿对象/资产、任务状态与失败详情一致。
4. 前端测试：真实任务阶段的页级进度、失败提示、没有图片/表格/公式时不展示虚假入口。
5. 本地 OER 评测：记录页数、各对象计数、bbox 覆盖率、图/表/公式抽样人工核验、对象跳转抽样、`hybrid-v4` 文本检索不回退、教材外问题拒答不回退。

验收报告必须分别说明“已编码”“自动测试”“本地开放教材验证”。若某对象类型没有可验证金标，只报告解析数量和人工抽样，不把它表述为检索或理解效果。
