# 教师审核台与学生学习空间：视觉实现基线

## 输入与范围

本基线依据用户在 2026-09-22 提供的六张 AI 图稿实现。图稿用于确认信息结构与交互意图，不要求逐像素复刻；用户明确允许根据真实工作流调整页面。

- 教师端以“教材发布工作台 / 解析审核”为主：章节导航、原页预览、对象 bbox、解析结果/教师修正、质量问题和发布门禁。
- 学生端以“教材阅读 + AI 教师”为主：目录、教材正文与选段、带页码证据的主对话、可独立关闭或带回主对话的局部追问。
- 当前为前端交互基线，示例教材内容是静态展示数据；不伪造后端成功状态，也不替代真实的鉴权、发布或检索接口。

## 设计决定

1. 使用统一的蓝灰教学工作台语言，但教师端强调审核与状态门禁，学生端强调连续阅读与有据回答。
2. 教师端将图稿中的“页面问题队列”收束为右侧对象检查器；这样原页、对象定位和修正输入可同时可见。
3. 学生端保留局部追问抽屉，不打断主对话；带回动作在主对话留下可追溯的新问题。
4. 图标通过 `@iconify/react` 的 Solar 图标集提供，避免把字符或手绘 SVG 作为操作图标。
5. 在中等宽度下，学生局部追问成为覆盖式抽屉；在窄屏下，教师检查器和学生 AI 教师顺序下移，避免关键内容被截断。

## 后续接入边界

- 教师页面应接入教材版本、解析任务、知识对象、教师修正、质量问题和候选索引状态接口；“构建候选索引”仅在质量门禁满足时可用。
- 学生页面应接入发布版本、页面/段落 bbox、问答 SSE、证据包和局部分支会话接口。证据不足状态必须继续明确表达，不能以普通答案掩盖。
- 页面视觉冻结后，再按 OpenAPI 契约替换静态示例数据；接口失败、无权和异步状态要使用已有统一错误语义。

## 验收

- 教师：可查看当前章节、对象 bbox、解析文本和质量问题；可切换至修正输入并保存草稿；未清除待确认问题时，索引动作给出门禁说明。
- 学生：可从选段打开局部追问，关闭抽屉，或将追问带回主对话；主对话显示教材页码证据和证据不足的拒答状态。
- 工程：`pnpm typecheck`、`pnpm lint` 和 `pnpm build` 必须通过。
