## 2. 产品定位与范围

### 2.1 已确认的目标

建设面向单校心理学部大学生的纯学业型 AI 导师，围绕学校课程资料帮助学生理解概念、辨析理论、学习研究方法、进行练习和复习。核心价值是基于可核查证据进行循序渐进的教学，而非通用聊天。

- 首期规模：500～3000 名注册用户，峰值同时在线 50～300 人。
- 客户端：响应式 Web + PWA，桌面优先，兼顾平板和手机。
- 学习方式：结构化课程学习与课程内自由提问并存。
- 课程资料尚未取得；系统不能绑定某门固定课程。
- 首期以一门真实课程验证闭环，再扩展多课程和跨课程关联。
- 数据结构预留 `organization_id`，首期不开发多学校入驻、计费或租户运营后台。

首门课程的成功标准分别覆盖内容准确、学生可独立完成学习流程、教师审核负担及新题独立作答表现。具体样本和阈值在第 17 节确认；能完成聊天流程不能单独证明教学有效。

### 2.2 知识建设路线

1. 课程资料驱动：只依据指定课程的已发布资料进行课程教学。
2. 支持多门课程；显式授权后提供跨课程关联，不默认混合检索。
3. 建立课程核心库、教师审核的课程扩展资料以及审核后的通用心理学库，回答时区分来源层级。

课程资料是课程口径的优先来源，不代表其任何陈述都天然正确。发现资料冲突、版本差异或疑似错误时，应并列说明、标记不确定性并交教师处理，不能隐藏冲突。

### 2.3 首版功能与非目标

首版包括课程知识库、引导学习、自由问答、题库与测验、学习证据、掌握度、间隔复习和三角色工作台。

班级和课程成员的基础关系属于首版权限基础；作业发布、截止时间、班级通知、复杂教师批改工作流及完整课程报告属于后续教学管理阶段。首版保留学生自选的基础复习提醒，正式测验仍需必要的结果复核能力。

近期不做：个人心理诊断、心理咨询、治疗建议、完整 LMS、教务/学分系统、社区、付费、原生移动 App、Windows 客户端、任意插件市场、自由多 Agent 群聊、学生任意代码执行、全量 GraphRAG。

## 4. 角色、身份与资源权限

| 角色 | 主要能力 | 不能默认拥有的能力 |
| --- | --- | --- |
| 学生 | 学习已加入课程、阅读获授权资料、提问、练习、测验、查看自己的进度 | 查看他人数据、访问未发布资料、配置模型、发布正式题目 |
| 教师 | 管理获授权课程、上传和审核资料、录题和出题审核、查看必要学情 | 查看任意课程、浏览全部自由对话、改写原始作答证据 |
| 管理员 | 账号、权限、模型、配额、运维、内容治理与审计 | 默认无限制读取学生完整对话 |

认证先实现平台账号、邀请/批量导入和账号生命周期；预留学校 OAuth2/OIDC/CAS 等适配器。正式接入协议待学校提供。账号关联不能仅凭未经验证的同名或邮箱自动合并。

授权由服务端统一执行 RBAC 与资源归属检查，覆盖 REST、SSE、后台任务、模型工具、引用预览、导出和对象存储下载。任何请求传入的 `course_id`、`organization_id` 均不是授权凭据。

平台管理角色与课程角色分开。同一用户可在不同开课批次分别担任教师或学生，不能把三类角色建成互斥的全局身份。`Course` 表示课程内容归属，`CourseOffering` 表示某学期或教学批次；成员、测验和学情均明确所属批次。批次可关联多个班级，但不扩展为完整教务管理。

授权判断统一考虑主体、课程/批次、资源版本、发布状态和使用目的。后台任务使用显式服务身份，并记录发起人和允许范围；缺少用户身份不能解释为拥有系统权限。任务开始、读取敏感资源和提交重要结果前重新检查相应权限。

教师默认读取掌握证据、答题记录、错误类型和经过最小化处理的学情摘要，不读取完整自由对话。摘要也可能泄露隐私，应排除个人生活披露和非教学内容。详细查看需要明确教学目的、合法授权范围和逐次审计；紧急运维访问同样不能绕过规则。

## 5. 总体技术架构

已确认采用模块化单体与独立 Worker，暂不上 Kubernetes。

```text
响应式 Next.js Web/PWA
        ↓ HTTPS / SSE
FastAPI API（可多实例）
        ├─ 身份、权限与审计
        ├─ 课程、班级与成员
        ├─ 教材、知识库与引用
        ├─ 教学会话与学习状态机
        ├─ 题库、测验与评分
        ├─ 学习证据、掌握度与复习
        └─ 学生、教师和管理员工作台
        ↓
教学运行时：编排器 → RAG / Model Gateway / 受限子 Agent
        ↓
PostgreSQL + pgvector / Redis / 对象存储 / 异步 Worker
```

技术基线：Next.js、FastAPI、PostgreSQL + pgvector、Redis、S3 兼容对象存储或相应 OSS 适配器、容器化部署。具体运行时版本、Worker 框架、中文关键词检索实现和 Reranker 型号在专项方案中选定，不预先锁定未经验证的版本。

| 模块 | 输入与输出 | 依赖及权力边界 |
| --- | --- | --- |
| 身份与权限 | 当前身份、资源 → 授权结果 | 组织和课程成员关系；不能由模型授权 |
| 资料服务 | 上传文件 → 原件、解析产物、审核版本 | 对象存储、Worker、课程权限 |
| 检索服务 | 问题、已授权版本 → 证据包 | 已发布资料、关键词和向量索引 |
| 教学运行时 | 学生输入、学习状态、证据 → 教学响应与状态建议 | 有界工具策略；不直接写成绩 |
| 测验评分 | 作答、题目版本、评分规则 → 评分证据 | 确定性服务；主观题不得默认自动定正式分数 |
| 掌握度服务 | 学习证据 → 状态及解释 | 版本化规则；保存可追溯依据 |
| Model Gateway | 最小化上下文、调用策略 → 模型输出及用量 | 云端或本地适配器；不持有业务发布权 |

### 5.1 端到端核心闭环

```text
教师上传资料 → 异步解析并生成证据对象 → 教师对照原件复核 → 发布资料版本
→ 学生阅读/提问/练习 → 装配最小学习上下文 → 在授权范围内检索证据
→ 生成教学响应 → 证据校验通过/修订/拒绝 → 展示回答及可定位引用
→ 学生作答 → 确定性评分或教师确认 → 追加学习证据
→ 更新掌握状态与复习建议 → 教师查看有依据的学情 → 调整课程内容
```

教材入库属于离线或异步内容管道，学生答疑属于在线教学运行，评分与学习证据属于独立业务提交。三者通过版本化标识和事件关联，不共享一个可被模型任意改写的状态对象。任何阶段失败都保留已确认结果并进入可解释状态，不以解析成功代替发布、不以生成成功代替校验、不以模型建议代替正式评分、不以阅读或点击代替掌握。

模块分别维护自己的业务写入规则。教学运行时只能提出状态或评分建议；正式评分、证据追加、课程发布由对应服务验证后执行。首版不因引入运行恢复、解析或复习组件而增加独立微服务体系。

## 6. 课程知识库与 RAG

### 6.1 文档导入与发布

首版支持 PDF、PPTX、DOCX、Markdown、TXT。扫描 PDF 进入 OCR 和人工质量复核；音视频转写和网页同步暂不实现。

```text
教师上传 → 权限/大小/格式/安全检查 → 隔离解析或 OCR
→ 章节和定位信息识别 → 分块及元数据绑定 → 自动质量检查
→ 教师审核/抽检 → 构建候选索引 → 检索测试 → 原子发布新版本
```

导入是可恢复后台任务，阶段状态、失败原因和重试次数可见。解析成功不等于索引完成，索引完成不等于教师发布。待审核、失败和未发布版本不可被学生检索。

保存原件、结构化解析产物、阅读文本、知识切片和索引配置。结构化解析产物保留段落、表格、图片、阅读顺序、页/段定位和解析质量；Markdown 是阅读或加工形式，不是唯一原始依据。切片包含组织、课程、资料、版本、标题/章节、原文、上下文关系、审核状态、版权范围、哈希、解析质量和稳定定位符。

教材采用“双通道”保存：结构化通道服务于检索与关系扩展，原始页面通道服务于核验、定位和可视化。两者通过稳定定位符关联；结构化解析不能覆盖或替代原始证据。最小证据对象分为 `TextEvidence`、`TableEvidence`、`ImageEvidence`、`FormulaEvidence` 和 `PageEvidence`，共同携带来源、版本、章节层级、定位、权限范围、解析方式、质量状态及派生关系。

知识分块采用章节层级和语义完整性，不把固定字符数作为唯一边界。定义、正文、案例、表格、图片、公式和图注可分别保存为有类型的证据对象，通过父章节、相邻内容、引用及说明关系连接。切片保存关系标识而非重复复制全部关联正文，运行时按问题和预算渐进展开。

表头与单元格关系、图注与图片关系、公式及实验示意图应保留可追溯对应。无法准确识别或定位时标为未知并进入复核，不能将未知位置默认为第一页或将空表格视为解析成功。解析器通过统一产物约定接入；Docling 等仅为候选，须用中文课程样本验证。

图片和曲线图至少保留原图、页码、页面区域、图注及相关正文。自动生成的图片说明、图表结构和数值均作为带置信信息的派生内容，允许教师修正；无法可靠恢复精确数值时不得依靠视觉估计生成数据表。视觉页面检索可作为文本检索的补充候选，但不替代原始文件、权限过滤和稳定定位。

教师解析复核界面采用原件与结构化结果对照：选择证据对象时高亮原页区域，可修改识别文本、对象类型、章节归属、图注/表头关系和知识点关联，并可标记重处理、暂不发布或确认。待复核对象、低质量页面、修改记录及受影响索引范围可查询。教师确认只覆盖实际审阅的对象或抽检范围，不把“打开过页面”记为审核完成；修订解析结果后重新评估相应索引和已继承审核状态。

每次发布形成清单，绑定审核过的资料版本、解析产物、切片配置和候选索引；发布切换必须完整生效，不能出现新元数据配旧索引。审核之后重解析或改变内容，须重新核对受影响的审核结果。任务说明区分整阶段重试与真正的分段续作，不因存在恢复游标就承诺逐页断点恢复。

定位规则：PDF 使用文件页序号，并可另存书面页码；PPTX 使用幻灯片序号；DOCX 优先段落/标题锚点，生成固定渲染副本后可补充渲染页码；Markdown/TXT 使用标题、行号或文本偏移。不能给没有固定分页的文件编造页码。原文与派生摘要分开保存，AI 摘要不能伪装为教材原句。

### 6.2 检索与证据充分性

```text
问题理解 → 授权过滤和当前课程版本固定 → 有界查询改写
→ 中文关键词检索 + 向量检索 → 融合 → Reranker
→ 相邻片段/父章节扩展 → 证据充分性判断
→ 基于证据生成 → 逐项引用存在性、归属和支持关系校验
```

检索按问题类型分流但保持同一证据合同：术语、原句和章节名称优先精确/关键词检索；自然语言和模糊描述采用关键词与向量混合检索；涉及图、表、公式或页面布局时增加多模态页面候选。命中后只扩展必要的父章节、相邻段落、图注和关联对象，不能一次把整本教材送入模型。

关键词路不能简单等同于 PostgreSQL 默认英文全文检索。中文分词、术语精确匹配和融合方式必须通过首门课程检索评测选择；首版不因该选择自动增加重型搜索集群。

对小规模课程建立授权范围内精确检索基线。采用近似向量索引时，分别评测课程过滤后的召回、结果不足和延迟，并评估迭代扫描；确有需要再采用分区。数据库执行计划中的过滤时机可能影响召回，不等于授权可以省略。所有返回结果仍必须满足授权条件，不向模型暴露越权候选。

检索候选、扩展上下文、引用解析和预览下载都执行权限检查，不采用先全库取回、再向模型声明不可引用的方式。前端或模型不能自行指定额外课程访问范围。

每个证据包保存来源 ID、资料版本、定位符、内容和检索分数。相关性分数不是事实正确率；低证据时允许预算内重试，否则明确说明资料不支持回答。检索失败与知识库确实未收录必须区分。

`EvidencePack` 是一次回答或出题运行的只读证据快照，至少记录原问题、问题意图、所需证据类型、课程/资料/章节范围、候选证据及其对象类型、召回通道、排序和扩展关系、授权判断、证据预算、检索配置版本、创建时间与哈希。它引用证据对象而不复制无界全文；运行结束后可用于复核，但权限撤销后不因快照存在而继续允许查看原文。

证据包除候选内容外，还保存来源类型、章节路径、对象类型、与问题的匹配方式、排序信息、扩展关系和当前授权结果。权限是运行时判断而不是永久属性；引用预览、原文件下载及历史会话重开时均重新校验。

### 6.3 引用与来源层级

概念定义、理论观点、研究结论、人物主张和课程要求应绑定可展开来源。教学类比、生成案例和临时题应明确标注为派生教学内容，不要求为纯鼓励语或交互指令伪造引用。

来源层级分别显示课程资料、教师审核课程补充、未来通用扩展知识。首版没有部署第三层时，不允许以通用说明名义静默调用模型记忆回答缺证据的专业结论。

引用校验包括：ID 真实存在、当前主体可访问、版本正确、定位可恢复、相关陈述获得支持。机器校验只能降低风险，不能宣称完全消除幻觉。

最终答案拆分为可核对的关键说法，并建立“说法—引用”对应关系。先进行确定性检查：引用存在、版本与课程一致、定位可恢复、原文未被撤回、当前主体可访问；再对有事实含义的关键说法检查引用是否真正支持。缺少支持的说法必须删除、改为不确定说明或触发有界补检索，不能仅因为附带了若干引用就判定答案可靠。

深度模型校验只用于高风险、低证据或教师指定场景，不把每次普通回答都交给一个独立校验 Agent。校验结果按答案、证据版本和校验规则缓存；模型复核仍可能出错，不能代替教师评审和离线测试集。

前端引用采用可展开证据侧栏：显示资料与版本、章节路径、页/段定位、原文及必要前后文，并标明支持答案中的哪一句。图片、表格和公式优先展示原始对象，可进一步打开原教材页面并高亮区域。权限撤销后侧栏不得依靠旧缓存继续展示内容。

证据校验形成独立结论而不是布尔装饰：

| 状态 | 含义 | 后续动作 |
| --- | --- | --- |
| `pass` | 必要引用、权限、版本、定位和内容支持检查通过 | 作为最终回答发布 |
| `revise` | 部分关键说法依据不足、表述超出证据或上下文不完整 | 删除/改写问题说法或预算内补检索，再次校验 |
| `reject` | 无可用证据、引用无效、越权、来源撤回或有限重试后仍不支持 | 停止相应结论，返回结构化说明或可执行的下一步 |

校验记录至少包含回答/运行 ID、规则版本、各检查项、受影响说法、失败原因、动作、尝试次数、最终状态和使用的证据包。修订次数受运行预算限制，不能让失败校验形成新的无限生成循环。面向学生只展示必要且可理解的原因；完整诊断信息进入授权审计和质量分析。

### 6.4 版本、删除与撤回

新会话默认使用最新发布版本；进行中的学习单元和测验固定使用启动版本，切换版本必须显式处理。索引记录 Embedding 模型、维度和分块配置，禁止混用不同向量空间。

旧题和历史回答保留版本关系，但不保证历史原文永远可见。版权撤回、权限撤销或依法删除后，预览和下载应停止；保留允许保存的最小审计/撤回标记，后台处理索引、缓存和副本。版本不可变不能被用作拒绝删除的理由。

撤回传播覆盖派生题目、解析、教学单元、会话摘要和已保存回答中的受限摘录。记录派生内容依赖的来源版本，按撤回原因暂停使用、脱敏、删除或重新审核；不能只删除原件后继续展示其复制内容。权限撤销优先于会话版本固定，进行中的运行应停止读取与输出受限内容。

## 7. 教学 Agent 与学习状态机

### 7.1 双模式

课程学习：进入课程并续接记录 → 确认本次目标 → 必要时检查基础 → 检索证据并短段讲解 → 学生尝试 → 针对困难调整帮助 → 独立处理新问题 → 回想与总结 → 保存续学位置 → 间隔后再次检验。

自由提问：识别课程范围 → 必要澄清 → 检索答疑及引用 → 可选理解检查 → 推荐相关单元。自由问答不强制每回合考试，也不因一次闲聊自动改写长期目标。

两者共享课程学习档案，保留模式和证据来源；未经确认不自动把学生从问答跳转到课程任务。

学习入口区分首次学习、继续学习和单点答疑。首次只做必要的基础了解，学生明确表示不会时直接示范；再次进入优先显示上次位置和未解决问题，不重复完整诊断；单点答疑完成后可直接结束。可跳过的“系统学习 / 解决疑问 / 复习”入口用于选择当前任务，不新增互不兼容的学习模式。

本次学习卡展示目标、当前步骤、完成依据及下一步，提供“继续学习 / 这里还不懂 / 先学到这里”。可根据学生可用时间调整内容量，但预计时间不是掌握时限。普通学习暂停保存未完成内容，不计失败；正式测验的暂停与提交仍服从测验规则。

### 7.1.1 版本化教学单元设计

知识切片解决“依据是什么”，教学单元设计解决“如何教”。每个单元的 `TeachingBlueprintVersion` 至少包含：

- 学习目标及前置知识；
- 核心概念、常见误解及对应来源；
- 推荐讲解顺序、例子与理解检查；
- 提示升级、直接讲解、暂停和退出条件；
- 练习要求、迁移任务及完成所需证据。

AI 可生成草稿，教师审核后发布。教学运行在单元目标与来源边界内调整表达，不擅自改写正式目标或完成标准。教学单元版本绑定知识库及知识点映射版本；来源撤回或实质修改后检查是否需要重审。课程内容是数据，不转换为学生可执行的 Skill。

### 7.2 自适应支架

教学动作包括追问当前想法、方向提示、关键概念、类比/反例/对比、局部讲解、完整讲解及迁移练习。通常先给最小必要帮助，并针对学生回答调整，而非机械走完全部层级。

后端 `TeachingRunPolicy` 控制课程范围、允许工具、检索预算、最长追问轮数、超时、提示层级和可写入内容。模型负责理解和表达，不能扩大工具权限、无限追问或决定正式分数。

学生在普通学习中可选择“直接讲解”。这是教学辅助使用记录，不应成为惩罚；该回合不能被误记为无提示独立掌握。正式测验期间服从第 8 节的辅助策略。学生说“懂了”只代表自我报告，不等于掌握证据。

### 7.2.1 讲解选择与帮助渐退

| 当前需要 | 教学动作 |
| --- | --- |
| 缺少定义、术语或符号知识 | 直接解释并给出处，不要求学生猜出事实 |
| 已有部分理解，但推理有缺口 | 只追问关键一步，不以问题结尾作为硬规则 |
| 相近概念混淆或忽略适用条件 | 使用对比例子、反例和条件变化 |
| 完全没有基础或持续卡住 | 完整示范，再让学生补完部分步骤 |
| 已能独立处理当前问题 | 减少帮助，转入新情境应用 |

帮助可以按“先尝试—提示—拆步—示范—学生补完—独立新题”调整，但不是必须依次通过的固定阶梯。连续追问未带来进展时必须改变方式，不只换措辞重复问同一个问题。示范后逐步减少帮助，并记录独立完成与提示后完成的区别。

错误分析区分术语不清、概念混淆、适用条件遗漏、论证不足，以及题目或参考答案本身可能有误；这些是待验证的解释，不是一次作答即可确定的学生标签。学生表示疲惫或不愿继续时可暂停、获取小结；不从沉默、耗时或错误直接推断心理状态。

### 7.2.2 定位疑问与理解检查

学生可在教材或讲解中选中具体文字，标记“词语不理解 / 这一步没跟上 / 想看例子 / 与前文矛盾”，并可补充自己的问题。疑问绑定原位置和内容版本，区分未解释、已解释但未检验、学生表示已解决、需要教师确认；AI 输出一次回答不自动关闭疑问，学生可重新打开。学生表示解决也不直接升级掌握状态。

疑问默认属于学生私人学习记录，教师端仍遵守最小可见规则。“需要教师确认”不自动转发原始对话或通知教师；需共享时仅在明确授权范围内提供必要的课程问题。来源撤回或版本改变时显示位置不可用或需要重核，不继续暴露受限摘录。

理解检查按目标选择简短复述、正反例辨析、情境应用、方法选择说明或推理纠错，而不是统一采用选择题或长篇讲解。关键概念可使用“学生当小老师”：用自己的话解释，再针对关键遗漏作有限追问。允许用简短说明、比较或选择等合适方式表达；语言流畅、自信和复述完整度均不能单独证明掌握。

### 7.2.3 回想、小结与续学

普通学习结束前可邀请学生简短回想本次重点及尚不确定之处，允许跳过并直接获取小结。小结依据有效学习记录，分别说明接触过的内容、独立完成的内容、仍需提示的内容和下次起点，不凭空生成进步或薄弱点。

阅读完成、疑问已解释、学生自报理解、即时练习通过和稳定掌握是不同状态。学习小结不是完成全部课程后的奖励；暂停也可生成，不含正式测验中尚未开放的答案。

### 7.2.4 情境学习入口

同一 AI 导师支持两种附着于当前页面的轻量情境，不创建彼此独立的人格或长期学习档案：

1. **题目学习教练**：绑定 `QuestionContext`，包含题目及版本、知识点、学生当前草稿、已用提示、可用资料和 `AssessmentPolicy`。帮助按理解题意、知识提醒、小提示、拆步、示范、学生补完和独立新题逐步调整。切换题目必须显式更换上下文，不能把上一题条件带入下一题。正式测验的辅助政策在检索、历史、引用预览和模型上下文各层同时生效。
2. **侧边独立提问**：从教材、AI 消息、题目或引用中的选区创建 `ContextThread`。保存父消息/资料定位、选中文字及偏移、必要前后文、课程与版本、相关引用和处理状态；只装配解决该局部问题所需的最小上下文。

`ContextThread` 与主 `Conversation`、`LearningSession` 分离。侧边回复默认不写长期记忆、不推进主学习步骤、不产生正式掌握证据；学生明确选择“带回主对话”“加入笔记”或“保存为待复习问题”后，才按目标服务的写入规则生成可追溯记录。带回时写入经确认的简短结论和来源链接，不复制整段侧边历史。

悬浮入口只是 UI 入口，不拥有额外资料权限。移动端不得遮挡题干、选项及提交控件；所有入口提供键盘、读屏和文字标签。正式测验禁止帮助时，仅保留操作与提交支持。

### 7.3 运行及回答合同

教学运行有独立 `run_id`、状态、事件序号、幂等键、资料版本、证据引用、调用预算和最终结果。状态至少覆盖已接收、读取上下文、检索、生成、校验、完成、降级、失败、取消。

区分跨回合的 `LearningSession` 与单次 `TeachingRun`：前者保存教学单元版本、当前步骤、提示层级和待回答问题，后者保存本次执行过程。正式作答和学习证据是独立业务记录，不能由运行 checkpoint 或聊天摘要替代。并发窗口须检查会话状态版本，旧运行不得覆盖后续已确认步骤。

每次运行记录教学策略、提示模板、模型及证据版本。会话摘要保留来源依赖和适用范围，使用前重新校验权限及版本；不能把历史摘要视为永久可信的教材或学生事实。

上下文治理采用“先隔离、再检索、后整理、必要时压缩”的顺序。系统消息、当前问题、正式题目、学生原作答、评分规则、原始教材证据、引用定位和未完成任务状态属于不可压缩核心；早期聊天可以形成结构化阶段小结，但必须保留原消息范围、生成时间、来源依赖和适用版本。压缩不能成为删除原记录或绕过撤回传播的方式。

可选的语义压缩只处理已经选定的冗长辅助上下文，并在中文心理学教材样本上验证。它不得改写引文、数字、定义、评分依据和权限信息；压缩结果参与回答前重新执行关键事实与引用校验。长期记忆不等于完整聊天记录，教学里程碑应写入独立事实源，而不是依赖对话摘要永久保存。

回答合同包括核心结论、一个下一步动作、分步说明、可选理解检查、引用和不确定性。并非每个回答都必须填充全部字段，不以空问题打断自然教学。

SSE 只展示真实执行事件。未经必要证据校验的内容应标为生成中，而非正式课程结论。重连按运行 ID/事件序号恢复，不能因浏览器重试重复计分。取消传播到工具和 Worker；无法撤销的已完成业务结果要明确告知。

流式草稿与最终答案分开标识。校验失败时撤回或替换相应草稿，明确显示失败原因或可用的降级结果，不将未通过内容留作最终答案。最终答案、状态推进和证据追加分别经过业务校验。只有在实际完成对应写入后才能发送成功事件；恢复时查询已提交结果，不重放产生新成绩。

运行增加循环保护：对工具名和规范化参数形成指纹，在滑动窗口内统计重复；达到警告阈值时要求基于已有结果作答或改变方法，达到停止阈值时丢弃重复调用并进入有界收尾。除完全相同调用外，再比较新证据数、未解决任务数和学习步骤状态，识别“参数略变但没有进展”的语义循环。合法的分页、不同证据检索及教师要求的重复检验不能被误判。

每次运行同时受最大轮数、工具次数、记忆检索次数、并发数、时间和费用预算约束。检测到无进展后，依次选择已有证据总结、改变讲解方式、提出一个明确澄清问题或说明无法继续；用户界面显示可理解的阶段结果，不暴露内部提示词或只显示“循环错误”。

LangGraph 的持久化能力可作为专项候选，但是否采用尚未确定；线程标识不提供课程授权，checkpoint 不提供正式成绩的业务事务保证。

### 7.4 受限子 Agent

出题 Agent 生成候选题；资料结构化 Agent 提取候选章节和知识点；学情总结 Agent 只读取被授权、最小化的教学证据。总编排器调用这些能力，子 Agent 不自由相互派发任务，不拥有题目发布、账号管理、正式评分或掌握度写入权限。

首选结构是“统一 AI 导师 + 受限能力”，而不是每个界面入口各自拥有自由 Agent。检索、图片查找、证据校验、出题、学情整理和复习建议可实现为工具或有界 Worker；是否以独立模型运行由专项评测决定，不在产品界面向学生暴露。

每项能力声明输入/输出结构、来源范围、工具白名单、预算、超时、幂等、可写目标和失败合同。模型可以提出结构化任务请求，但不能自行扩大权限、创建未注册子 Agent 或编写新的无限制工具清单。相互独立且只读的检索可并行；存在数据依赖、发布、评分或状态写入的步骤必须顺序执行。子能力之间不自由转派任务，所有结果回到编排器接受业务校验。

文档和检索文本是数据，不是系统指令。任何来源中要求忽略权限、执行命令、透露秘密或调用外部工具的内容必须被视为不可信输入。

## 8. 题库、测验与评分

教师手动录入/导入与出题 Agent 共用题目模型。题目包含题干、题型、知识点、难度、答案、解析、证据定位、评分规则、生成方式、审核人及版本。

正式题流程：选择章节与目标 → 检索 → 生成候选 → 自动检查答案/解析一致性、范围和重复 → 教师编辑审核 → 发布。任何内容修改形成新版本；题干含义、选项、答案、解析、来源、知识点或评分规则改变均需重新审核。纯展示调整的审核继承规则在专项中明确，不能由模型自行判定免审。

AI 临时题可用于即时练习，必须显著标识、不计正式成绩、不单独触发“已掌握”，仍需来源和基本校验。生成失败时明确失败，不能伪装成教师题库内容。

正式测验绑定已审核题目版本和服务端评分规则。不能将标准答案或评分密钥提前发送给前端。提交事务和幂等键避免重复计分，修改成绩以追加复核记录保存，不覆写原始作答。

客观题评分结果绑定作答、题目版本、参考答案版本、评分规则版本和评分服务版本，并生成可复核的结果摘要；相同输入与同一规则应得到相同结果。教师复核或规则变更产生新的 `ScoreRevision`，通过替代关系确定当前有效结果，不修改原始作答或静默覆盖已发布分数。主观题的模型输出只保存候选评价、依据及模型版本，正式成绩仍遵守教师确认规则。

学习报告和可视化不接受模型自由生成数字。图表引用版本化 `VisualizationDataset`，记录查询范围、样本数量、缺失情况、单位、标签、聚合规则、生成时间和内容哈希；渲染前检查数据集身份及完整性。模型可以依据同一数据集生成文字解释，但不得改变数据值或把推测补入空缺。报告中的结论、图表和底层学习证据建立可追溯关联。

### 8.1 测验期间的内容与辅助隔离

资源区分学生教材、教师参考、答案解析和评分规则，并分别设置可读用途。教师的出题检索权限不沿用为学生答疑权限。

正式测验发布前必须确定是否开卷、是否允许 AI 辅助、可用帮助范围以及答案/解析开放时机，并在开始前向学生展示。策略同时约束题目页面、RAG、上下文扩展、引用预览和会话历史中的受限内容；答案不能通过换一个提问入口被读取。

不允许辅助的测验期间，平台关闭该测验范围的答疑与讲解，保留提交和操作帮助；允许辅助时仅开放明确的资源和动作。不承诺识别或阻止学生在平台外求助，不扩展为监考系统，也不宣称可以完全消除模型推断答案的风险。哪些测验采取何种规则仍由教师确认。

题型范围尚未批准。客观题可确定性判分；若纳入正式简答/论述题，模型仅提供候选分和证据，正式分需教师确认，或另行批准经过验证的评分机制。即时练习可以给形成性反馈，但应与正式成绩清楚区分。

## 9. 掌握度、学习证据与复习

第一版采用可解释规则引擎作为正式判定源，并纳入 BKT/IRT 影子评估路径。影子结果不改变正式成绩、掌握状态或对学生的推荐。

证据记录知识点、题目版本、作答、评分来源、提示使用、重复程度、发生时间及关联运行。正式测验是主要证据；即时练习辅助；同题短期重复降权；迁移题与间隔复习提供补充证据。

状态为未学习、学习中、需巩固、基本掌握、已掌握。规则、阈值和证据权重必须版本化；具体数值在专项规格中经教师确认。界面显示状态依据，不能将启发式分数包装为已校准的真实概率。

单次错误只记录待确认困难，不贴长期能力或心理标签。没有证据、没有作答和数据缺失不能按零分处理。复核结果产生新证据并重新聚合，保留变化过程。

BKT 与 IRT 不是同一个模型：前者关注知识状态随作答变化，后者需要题目与能力标定。冷启动无合格数据时标为未校准或不输出；合成数据仅用于软件测试。影子结果启用前需完成数据充分性、拟合/校准、泄漏检查、公平性及教师可解释性评审。

间隔复习根据学习时间、证据和课程节奏调度，教师可调整，学生可管理提醒。提醒与任何 PWA 通知必须遵循用户选择，不默认授权发送。

掌握度、正式成绩与复习调度分别管理。复习记录区分独立回答、提示后回答和自我报告，不能把自评“容易”直接转换成正式掌握证据。py-fsrs 可作为复习算法候选，pyBKT 可作为 BKT 影子评估候选，均不构成本轮选型批准；记忆保持概率、BKT 知识状态和 IRT 能力估计不得混为同一指标。

复习采用“先尝试回忆—按需看提示或原文—用变化后的问题确认”的过程，避免一进入错题就先展示答案。概念记忆可用短问题，综合应用保留案例、理论比较及研究设计，不将所有知识做成闪卡。除错题外，也安排部分已答对内容的延迟检验。

复习积压时允许减少本次任务量、调整顺序或稍后继续，并展示剩余项目，不因逾期或暂停扣减掌握状态；状态变化应基于新学习证据及经教师确认的规则。具体复习间隔、工作量和判定阈值不在本轮预设。

### 9.1 学习记忆分层与时效

记忆分为当前任务状态、相对稳定的学习偏好、经多次证据确认的学习事实和原始学习事件。课程知识与学生记忆分别治理；教材内容进入课程知识库，不因被学生讨论过就复制为个人长期记忆。单次错误、自评、临时侧边提问和模型推断默认不形成稳定画像。

记忆读取采用渐进加载：先返回各类记忆数量、主题和短摘要，再按当前课程、知识点、时间和任务读取少量详情。每次装配设置条数、相关度和 token 预算，保留来源事件、形成规则、置信状态及更新时间；模型不得借“读取记忆”绕过课程或教师可见性权限。

过时处理采用“保留来源、标记替代、默认隐藏旧结论”，而不是简单硬删或声明重要信息永远有效。派生事实记录有效起止时间、替代关系和当前可见状态；原始学习事件在获准保留期内可追溯。依法删除、用户删除权、版权撤回和学校数据政策优先于历史保留，删除不得被“不可变记忆”阻挡。

记忆写入由业务规则确认：更新学习任务、追加原始事件、形成或替代学习事实分别处理。模型只提交候选事实和来源，不能直接覆盖正式成绩、掌握状态或教师确认内容。学生可以查看形成依据，并按学校规则纠正、导出或申请删除。

记忆整理任务对语义重复、同一事件的多次写入和已经被新证据替代的候选事实进行聚合。整理结果形成新的摘要或事实节点，保存输入记录、整理规则/模型版本、原因和内容哈希；原始作答、正式成绩、教师反馈及有效期内的学习事件保持独立。整理失败、超时或低置信时放弃候选结果，不损坏原记录。

前瞻性“可能卡点”只允许作为可关闭的实验建议，必须记录预测与后续是否命中，不直接进入稳定画像、正式掌握度或教师评价。教练质量可统计证据支持率、无效重复率、帮助后独立完成率、预测命中/误报和学生主动解决率，但这些指标用于改进系统，不用于评价学生能力，也不能把对话更长解释为教学更好。

## 10. 页面结构

学生一级入口：首页、课程、AI 导师、练习、成长。页面不暴露模型、Embedding、MCP、数据库等配置。

教师入口：工作台、课程管理、资料中心、题库中心、学情中心、教学配置。发布课程内容和查看学生数据分别授权。

管理员入口：用户与身份、模型与配额、后台任务、内容治理、审计与系统运维。

桌面课程页支持教材与导师并排；移动端采用切换/上下结构。引用以编号或来源标记打开证据侧栏，侧栏展示原文、必要前后文、版本和定位，并可打开原教材页面高亮文本或图片区域。所有关键页面覆盖加载、空数据、处理中、无权限、不可用和可恢复失败状态。

课程首页突出续学和本次学习卡；教材与讲解区域支持定位疑问及侧边独立提问；练习页提供不遮挡内容的题目学习教练；学习结束展示可直接获得的小结与下次起点；复习列表区分概念记忆和综合应用。上述入口沿用现有页面，不新增复杂导航或让学生选择内部 Agent。

主要学习与审核流程支持键盘操作、可见焦点、读屏标签、字号缩放及足够对比度，不仅以颜色表达对错或状态。长任务失败提供当前角色可执行的下一步；教师没有系统配置权限时，应引导联系管理员而非跳转到无权访问的设置页。班级统计显示样本数量与缺失范围，不将少数参与者当作全班结论。

PWA 提供安装、公共静态资源缓存及受支持浏览器中的基础通知。不承诺离线模型或正式提交，不缓存敏感对话、答案、学情或受版权限制原文到公共 Service Worker 缓存。退出或切换账号时清理相应本地私有状态。

## 11. 数据模型与事实来源

```text
Organization
├─ User / PlatformRole / Identity / Session / ServicePrincipal
├─ Course / CourseOffering / Class / CourseMembership
│  ├─ CourseUnit / TeachingBlueprintVersion / KnowledgePoint / Prerequisite
│  ├─ KnowledgePointMappingVersion / KnowledgeBaseVersion / PublicationManifest
│  ├─ SourceDocument / ParsedDocument / SourceLocator / KnowledgeChunk
│  │  └─ EvidenceObject / EvidenceRelation / EvidenceValidation
│  └─ Question / QuestionVersion / Assessment / AssessmentPolicy / AssessmentItem
└─ LearnerCourseProfile（绑定开课批次）
   ├─ Attempt / ScoreRevision / VisualizationDataset / ReportArtifact
   ├─ LearningEvidence / MasteryState / ReviewSchedule / ReviewLog
   ├─ Conversation / ContextThread / LearningSession / TeachingRun / RunEvent
   └─ Citation / ClaimCitation / LearningQuestion / LearnerMemoryFact
      └─ MemorySupersession / MemoryConsolidation

配套：ImportJob / OutboxEvent / DerivedContentDependency
      ModelUsage / AuditEvent / ContentReview / DeletionRequest
```

`User` 是登录身份，`LearnerCourseProfile` 是课程学习状态。跨课程不默认共享对话、薄弱点或学习画像。知识点图谱首版属于课程内部先修关系，不等于全局心理学实体知识图谱。

以上是概念实体，不要求一实体对应一张表。开课批次之间可经授权复用内容版本，但不默认共享学生记录或将上学期掌握状态迁入新批次。知识点映射变化须有明确迁移或重新评估规则，不能悄悄把旧证据绑定到不同知识点。

`LearningQuestion` 表示学生的定位疑问，与题库 `Question` 分开；记录归属、来源位置和版本、疑问内容及处理状态。处理状态不作为正式掌握证据，隐私与删除规则和其他私人学习记录一致。

`ContextThread` 是绑定选区或当前页面对象的局部讨论，记录父上下文和最小来源快照，但不等同于主会话分支的自动合并。`ClaimCitation` 保存答案关键说法与证据对象的对应；`EvidenceValidation` 保存检查规则、结果和版本。`LearnerMemoryFact` 是从原始学习事件产生的候选或已确认事实，`MemorySupersession` 表示新事实对旧结论的替代，不用于阻止依法删除。

`ScoreRevision` 关联作答、题目/答案/规则版本及当前有效关系；`VisualizationDataset` 是报告和图表的确定性数据来源，不能由模型文本代替。`MemoryConsolidation` 保存重复合并和摘要整理的输入、规则、结果及失败状态，不赋予整理任务修改正式证据的权限。

PostgreSQL 是身份权限、课程发布、正式测验、证据及任务业务状态的事实源。对象存储保存文件字节，数据库保存归属与版本。pgvector 保存可重建向量索引。Redis 是可失效缓存、限流和队列传输设施。

后台任务的业务状态、幂等标识和恢复凭据持久化到数据库；队列丢失后应能对账重派。实现按至少一次执行设计，Worker 必须幂等，不宣称依靠 Redis 可以保证业务恰好执行一次。

业务变更与待投递任务使用同一事务记录（事务发件箱），投递失败可重试；任务有租约和执行代次，提交结果时拒绝已过期执行者的写入。任务幂等键结合业务对象与版本，不能只靠短期内存缓存。发布和评分等重要结果在数据库中保证不会因重派重复生效。对象存储产物先暂存，数据库确认后成为可用版本；未完成产物通过对账处理。

## 12. 安全、隐私与学业边界

模型网关最小化发送上下文，剔除无关身份信息；用户主动输入的个人信息也需要检测和处理。必要课程原文外发还须符合教材授权和学校数据要求，脱敏不等于自动取得外发许可。

生产密钥只存服务端 Secret，日志、错误、Trace 和诊断不能输出密钥、完整私有上下文或他人数据。第三方 Trace 默认不接收原始学生内容，启用须有明确的数据治理配置。

安全控制覆盖登录限流、会话撤销、凭据恢复、Cookie/CSRF 或对应认证边界、上传类型与大小限制、解析资源隔离、存储下载授权、提示注入和跨课程访问。具体认证合同在身份专项中确定。

个人心理诊断和治疗请求转为边界说明与专业求助建议；明显紧急风险表达进入最小安全转介，停止正常教学。转介只使用经学校审核和定期核验的资源，不由模型编造联系方式。

区分教材引用、虚构教学案例、一般学术讨论与学生本人当前的求助。不能仅凭出现自伤、障碍或危机等词语就拒绝课程教学；语境不明确时作简短澄清，明确紧急求助不被反复澄清所拖延。转介文案、适用边界和资源维护责任在专项中由学校审核，本文不提供临床判定标准。

风险推断不能成为课程掌握度或心理疾病标签。首版不自动通知教师、家长或学校，不将风险自动写入一般学情摘要。未来预警需要单独的制度、法律评估、权限与审计设计。

数据保留、个人导出、删除和版权撤回应有明确流程。实际期限、处理依据和转介清单在真实学生上线前经学校确认；本文不是法律或临床合规结论。

## 13. 生产部署、容量与故障恢复

### 13.1 拓扑与发布

HTTPS 网关/负载均衡连接约两个 Next.js/API 实例，配独立 Worker、PostgreSQL、Redis 和对象存储；CDN/WAF 可按供应商接入。私有内容不进入公共 CDN 缓存。

开发、测试、生产隔离账号、数据库、存储和模型配额。CI 构建固定版本镜像，服务器运行构建产物；发布包含迁移预检、健康检查、灰度/滚动或蓝绿、错误观察及回退。破坏性数据库迁移不能依靠回退旧镜像自动恢复，应采用兼容迁移和单独恢复计划。

两个进程或两个容器不等于高可用：实例位于同一宿主机仍共享故障域；数据库、Redis 和网关的可用性需分别评估。硬件规格和托管/自建方案经容量及预算评估后锁定。

### 13.2 容量与模型治理

50～300 人在线是产品目标，不等于 300 路并行生成。容量验收需分别定义在线连接数、活跃生成数、模型请求率、上下文长度、RAG 负载、测验突发提交和解析任务压力。

模型网关统一超时、取消、重试、供应商熔断、费用记录和按用户/课程/供应商的配额。备用模型需要通过相同引用和教学评测，并符合数据外发范围；不能把降级视为绕过证据或安全策略的许可。

交互答疑、批量出题和解析/OCR 分别限制并发及资源，避免大文件导入挤占正在上课的请求。超出容量时明确排队、暂停或拒绝受理，提供可理解的状态；同一业务重试不得形成无限调用和费用增长。Worker 框架保持候选状态，不因恢复需求默认引入重型工作流平台。

### 13.3 故障合同

| 故障 | 学生/教师可见结果 | 数据保护 |
| --- | --- | --- |
| 文档解析或 OCR 失败 | 阶段和可重试原因 | 保留原件，不发布损坏版本 |
| Embedding 失败 | 候选版本未索引 | 保持当前发布版本可用 |
| 检索超时 | 来源核验未完成 | 不伪装成知识库未收录或强答 |
| 模型失败 | 可重试或经授权备用模型 | 不生成虚假分数和进度 |
| SSE 断线 | 查询运行结果/恢复事件 | 不重复业务写入 |
| Redis 或 Worker 故障 | 排队/暂停/重试状态 | 数据库对账恢复任务，避免重复发布 |
| 任务提交后未成功投递 | 任务仍显示待处理 | 事务发件箱重派，不丢任务 |
| 超时 Worker 延迟返回 | 使用当前有效运行结果 | 过期执行者不能覆盖新结果 |
| 生成内容未通过校验 | 草稿撤回或替换并标明状态 | 不记为最终结论或掌握证据 |
| 资料撤回 | 原文及受影响内容暂停或受限 | 传播至题目、摘要及其他派生内容 |
| 课程权限撤销 | 停止后续访问 | 重校验引用、下载和后台任务 |
| 测验重复提交 | 返回已有结果或明确冲突 | 事务、幂等键保护评分 |

监控覆盖 API 延迟、错误率、连接数，模型首字/总耗时及费用，检索证据不足与引用失败，队列长度和任务耗时，测验提交、越权事件及基础服务健康。

数据库备份、时间点恢复能力、对象版本、异地副本、保留周期和 RPO/RTO 在生产专项中明确。必须实际演练恢复与验证引用文件可用，不能仅用“已开启备份”作为验收。

## 14. 测试与验收

### 14.1 内容与教学评测

建议首门课程由教师审核至少 100 个 RAG 问题和 30～50 个教学场景，覆盖单片段、多章节、相近理论、模糊提问、资料外问题、错误前提、恶意指令及跨课程访问。

指标包括检索召回和排序、答案支持性、定位正确性、资料外拒答、引用泄露、教学步骤推进、提示适配、过早泄题和掌握证据可追溯性。生成题另测正确性、歧义、难度、知识点匹配、答案解析一致性及重复率。

RAG 评测分别报告：正确证据是否进入候选集、是否排在靠前位置、每个关键说法是否有真实且足够的引用、跨片段上下文是否补齐、同一问题多次检索的核心证据是否稳定、资料外问题是否正确拒答，以及延迟和校验成本。多模态场景另测图片/表格定位、图注关联、原图可访问性、自动结构化准确性和无法可靠识别时的克制输出。稳定不要求每次候选完全相同，但来源版本、核心证据和回答依据不能无规律漂移。

教师评审是专业准确性的必要环节。LLM-as-judge 只能辅助，评测集应分开发集与冻结验收集，避免只针对固定题调提示词。具体通过阈值、抽样和分歧裁决须在首门课程评测规格中批准，不能用未经运行的百分比宣称达标。

评测分为三层，分别报告，不合并成一个“教学效果分”：

| 层次 | 核心问题 | 证据 |
| --- | --- | --- |
| 内容质量 | 资料是否被正确理解和引用 | 教师核对原文、定位及结论支持关系 |
| 教学质量 | 顺序、提示和反馈是否适合当前学生 | 经教师审阅的多回合教学场景 |
| 学习效果 | 脱离帮助后能否完成新题并在稍后保持 | 独立迁移题、延迟复习与试点记录 |

学习效果评估不得使用已反复练习的原题代替迁移检验。样本、辅助使用、缺失数据及评价限制应披露；如需宣称因果性的学习提升，须另行确定合适的研究设计，不能由试点前后分数变化直接推断。

新增必测场景：教师答案混入检索、跨开课批次访问、撤回资料的派生内容、图表识别错误、资料版本切换、会话摘要过期、压缩改变关键数字或定义、引用存在但不支持结论、连续提示后的掌握误判、侧边提问误写主记忆、切换题目后上下文串题、正式测验经悬浮助手泄题，以及学术案例与个人求助的区分。补充验证 `pass/revise/reject` 各分支、修订后仍失败、证据包快照撤权、教师只审核部分对象、重复记忆整理失败、评分规则变更和图表数据被模型改写。第三方评测工具与裁判模型同样遵守数据外发要求。

学习过程验收补充：续学不重复完整诊断；事实问题可以直接解释；持续卡住后改变帮助方式；示范后能减少提示；疑问未解决可保留及重开；表达形式不影响学科要求；暂停可获得小结且不记失败；复习先尝试再按需揭示答案；正式测验限制不能被小结、疑问或复习入口绕过。记录学生退出与再次进入能否衔接，不将更长对话或更多点击当作更好学习效果。
