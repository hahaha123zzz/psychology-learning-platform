## 0. 这次冲刺的唯一目标

明天中午前，不以“P0-P10 全部完成”“V1 整体验收通过”为目标，而以一条真正连续的学生学习闭环为目标：

```text
学生登录
→ Student Home 看到当前任务
→ 进入学习页
→ 阅读教材
→ 向 Tutor 提问
→ Tutor 给出有教材依据的解释
→ 点击 Citation 回到教材原页并定位/高亮
→ 针对章节/知识点进入交互式练习
→ 答错后获得提示/纠错
→ 错题/薄弱点进入 Review
→ Growth 显示“正在学习 / 需加强 / 待复习”等可解释状态
→ 修改回答偏好
→ 下一次 Tutor 回答体现偏好
```

附加闭环：

```text
选择教材中的图片/表格/局部内容
→ 基于 Figure/Table/附近正文进行解释
→ 显示来源
→ 可继续“解释 / 举例 / 出题”
```

如果现有 Mini Lab 已经稳定，则保留为加分项；**不为了本次截止日期扩建 AI 生成实验工作流**。

# 1. 范围冻结

## 1.1 明天前必须完成：P0

### A. 学生首页
- 展示唯一或主要 `Current Learning Task`。
- 提供继续学习入口。
- 提供“待复习”入口。
- 提供章节/知识点练习入口。
- 不做复杂 Dashboard。

### B. 学习页 / Reading Studio
- 教材目录。
- 教材正文/Reader。
- Tutor。
- 支持从 Tutor 的证据引用打开教材。
- 支持教材文本/图片/表格局部上下文进入 Tutor。
- Tutor 是学习工作区中的能力，不是整个产品本身。

### C. Tutor + ZIP 微观教学循环
至少实现/接通以下思路：

```text
Conversation Router
→ Strategy Router
→ Lesson Mini Planner
→ Question Designer（需要时）
→ Quality Checker
→ LearningResponse
```

初版策略最少支持：

```text

HINT

MICRO_CHECK

```

### D. Citation → Reader
必须跑通：

```text
Tutor 回答
→ Evidence/Citation
→ 打开 Reader
→ 正确教材版本
→ 正确页
→ 能定位或高亮目标
```

### E. Practice
不能只做聊天式“一道题问完再来一道”。

学生至少能：
- 按章节选练习。
- 按知识点选练习。
- 一次进入一个 Practice Session。
- 初版题型支持：
  - 单选
  - 多选
  - 判断
  - 简答

已有正式 Assessment 如果稳定，可以保留入口；不要为了本次冲刺重写正式测评系统。

### F. Review
- 读取现有 Review / Wrong Answer / Mastery 等已有状态。
- 展示当前需要复习的知识点。
- 给出简单理由，例如：
  - 最近连续答错
  - 需要多次提示
  - 已到复习时间
- 点击后复用 Practice Session，不新造另一套 UI。

### G. Growth
第一版只需要清晰、可解释：

```text
已比较稳定
正在学习
需要加强
待复习
最近容易混淆
```

点击后能看到依据或最近证据。

### H. Presentation Preference
至少做到：
- 简洁 / 平衡 / 详细。
- 概念优先 / 例子优先 / 自适应。
- 用户主动设置后，下一次 Tutor 回答真的发生变化。
- 不偷偷根据一次行为生成稳定人格/能力标签。

### I. 基础 Figure/Table 问答
不做高级视觉检索。

最低实现：

```text
Figure/Table object 或 Reader 选中对象
→ caption
→ nearby text
→ 相关知识点/对象关系（已有则用）
→ Tutor
→ FigureExplain / TableExplain
→ Citation
```

所有窗口共用：

## 5.1 为什么用“追加事件日志”，而不是所有窗口一起编辑表格

多人/多 Agent 同时编辑同一个 Markdown 很容易覆盖彼此内容。

因此：

> **共享文档采用 APPEND-ONLY（只追加）事件流。**

所有窗口：
- 可以读取整个共享文档。
- 汇报时只在文件末尾追加新事件。
- 不修改别人已经写的内容。
- 不重排旧内容。
- 不删除旧事件。

CTRL 也尽量通过追加 `SNAPSHOT / TASK / DECISION / MERGE` 事件管理，不依赖修改顶部状态表。

## 5.2 事件格式

```text
- [2026-10-05 19:30] [CTRL→UI] [TASK] UI-001 | 完成 Student Home 到 Learn 的真实 API 跳转 | priority=P0

- [2026-10-05 20:18] [TUTOR→CTRL] [BLOCKED] TUTOR-002 | 需要确认当前 Evidence schema 字段 | files=...
- [2026-10-05 20:22] [CTRL→ALL] [DECISION] D-004 | 不新增第二套 Evidence model，复用 xxx
```

### 固定状态
- `TASK`
- `START`
- `PROGRESS`
- `DONE`
- `BLOCKED`
- `DECISION_REQUEST`

- `HANDOFF`
- `MERGE`

# 6. “完成或等待时不要停止”的轮询机制

这是本次并行协作的强制规则。

每个窗口完成当前任务后：

1. 跑自己的最小验证。
2. commit。
3. 在共享文档追加 `DONE/HANDOFF`。
4. 检查共享文档是否有新任务。
5. 如果没有新任务，进入 60 秒轮询。
6. 共享文档变化时自动退出等待。
7. 窗口重新读取末尾事件。
8. 有给自己的新任务就立即执行。
9. 没有则再次运行等待命令。
10. 只有 CTRL 发出 `[STOP]`，或用户主动终止时，窗口才能结束。

## 6.1 PowerShell 等待脚本

项目外公共目录保存：

```text
student-demo-control/wait_for_shared_change.ps1
```

内容：

```powershell
param(
    [string]$SharedDoc = ".\STUDENT_DEMO_SHARED.md",
    [int]$IntervalSeconds = 60
)

if (-not (Test-Path $SharedDoc)) {
    Write-Error "Shared document not found: $SharedDoc"
    exit 1
}

$lastHash = (Get-FileHash $SharedDoc -Algorithm SHA256).Hash
Write-Host "Waiting for shared document changes: $SharedDoc"
Write-Host "Polling every $IntervalSeconds seconds..."

while ($true) {
    Start-Sleep -Seconds $IntervalSeconds

    if (-not (Test-Path $SharedDoc)) {
        Write-Warning "Shared document temporarily missing. Continue waiting."
        continue
    }

    $newHash = (Get-FileHash $SharedDoc -Algorithm SHA256).Hash

    if ($newHash -ne $lastHash) {
        Write-Host "Shared document changed."
        Write-Host "Latest events:"
        Get-Content $SharedDoc -Tail 80
        exit 0
    }
}
```

从任意 worktree 调用：

```powershell
powershell -ExecutionPolicy Bypass -File ..\student-demo-control\wait_for_shared_change.ps1 `
  -SharedDoc ..\student-demo-control\STUDENT_DEMO_SHARED.md
```

### 注意
这是“等待一次变化后退出”的脚本，而不是永不返回的死循环。

窗口被唤醒后：
- 读取新事件；
- 处理任务；
- 没有任务则再次执行脚本。

这样 Agent 可以继续工作，而不是被一个永久阻塞命令卡死。

# 10. TUTOR + ZIP 窗口：完整提示词

---

## 【TUTOR 窗口提示词】

你负责把 ZIP Tutor Engine 中最有价值的“微观教学循环”融入 **现有 Tutor Runtime**。

你的 worktree：

```text
wt-tutor-runtime
branch: demo/tutor-runtime
```

### 最重要的约束

> 不能把 ZIP 变成第二套平台后端。

不要重写：
- 现有 RAG。
- 现有 Evidence。
- 现有 Student Model。
- 现有 Memory。
- 现有 Assessment。
- Course Release。
- 权限系统。

### 先做代码盘点

确认：
- 当前 Tutor 入口。
- Tutor SSE contract。
- Current Learning Task。
- Student State API/service。
- Evidence 注入方式。
- Review/assessment 上下文。
- Preference 当前存储。
- 是否已有 Router/Policy/Planner。

已有能力优先复用。

### 目标架构

只做本次需要的最薄层：

```text
TutorContext
→ Conversation Router
→ Strategy Router
→ Lesson Mini Planner
→ 必要时 Question Designer
→ 现有 Retrieval / Evidence / Student State
→ Quality Checker
→ 现有或最小扩展的 LearningResponse
```

### TUTOR-001 Router
最少区分：

```text
QA
LEARN
PRACTICE_HELP
REVIEW_HELP
```

不要做几十种 Intent。

### TUTOR-002 Strategy Router
最少：

```text
EXPLAIN
HINT
EXAMPLE
MICRO_CHECK
MISCONCEPTION_REPAIR
```

策略必须受：
- 当前任务
- Assessment policy
- Student state
- Preference
- Evidence availability

约束。

### TUTOR-003 Lesson Mini Planner
只规划当前 1–3 步。

示例：

```text
先解释核心概念
→ 给例子
→ micro-check
```

不要做长期课程规划器。

### TUTOR-004 Question Designer
只用于非正式学习中的临时 micro-check。

要求：
- 不自动进入正式题库。
- 不覆盖已审核题库。
- 正式 Assessment 不走这套临时题生成逻辑。

### TUTOR-005 Quality Checker
最低检查：
- 是否有需要的 Evidence。
- Citation 是否存在/合法。
- 是否越过 Assessment Policy。
- 结构化响应是否可渲染。
- 如果证据不足，是否应该降级/拒绝断言。
- Preference 是否被应用。

### TUTOR-006 Preference Wiring
至少确认：
- response length
- concept-first / example-first

真的影响输出策略/呈现。

### TUTOR-007 学习证据
Tutor 可以产生学习事件/证据候选。

但：
- 一次答对 ≠ 自动掌握。
- Tutor 不直接把 mastery 写死。
- 继续走现有 Student Model/资格化逻辑。

### 输出要求

如果仓库已有 Tutor response schema：
- 优先扩展，不重造。

如果确实要新增 block：
- 先向 CTRL 发 DECISION_REQUEST。
- CTRL 冻结字段后再实现。

### 任务交付

每个可独立合并的改动：
- targeted test。
- commit。
- 共享文档 DONE + SHA。
- 等待新任务。

阻塞时不要停：
- 先发 BLOCKED。
- 如果还有不依赖的 TUTOR 任务，继续做。
- 没有则运行 60 秒共享文档轮询。

只有 CTRL 发 `[STOP]` 才退出。
