## 故障结果

| 故障 | 注入方式 | 页面/API 观察 | 数据库副作用 | 结论 |
|---|---|---|---|---|
| SSE 收到首个 delta 后 TCP 中断 | 故障 API 在真实 Uvicorn/HTTP 流中暂停响应，客户端取消 TCP 流；见 `tutor_tcp_probe.py` 的 `after_first_delta` | 客户端收到 delta，未收到 `done`；同一 `client_turn_id` 重试返回 `done(saved=true)` | 中断时 0 条半回合记录；重试后恰好 student+tutor 各 1 条 | 真实 TCP 故障通过；不同于 ASGI iterator 单测 |
| SSE 持久化后、done 送达前 TCP 中断 | 故障 API 在真实 HTTP 流的 `done` 边界暂停客户端流 | 客户端未收到 done；同 key 重试返回 `replayed=true, saved=true` | 中断前完整 2 条回合记录；重试后仍为 2 条，没有重复写入 | 真实 TCP 响应丢失通过 |
| 测评答题断网、并发旧版本写入 | Headless Chrome CDP `Network.emulateNetworkConditions(offline=true)`；另标签保留旧 `answer_version` | 离线选择仍显示在页面并提示保存失败；联网重试后提示清除；旧版本标签收到冲突，刷新恢复服务端答案 | 保存一条当前答案；旧版本写入为 HTTP 409，不覆盖服务器值 | 浏览器模拟断网/乐观锁通过 |
| 截止时离线、截止后提交恢复 | 60 秒截止测验；截止前两个标签同时模拟断网，截止后恢复网络并分别点击恢复 | 两页均显示“重试提交已保存答案”；联网后两页均显示结果。重开页面的独立恢复验收读回同一 Attempt 的 `graded` 结果，结果 API HTTP 200 | Attempt `01M43624CX3PGZ26GP0QPR46EG` 最终 `graded`；`attempt_answers=1`、`answer_submitted` 事件 `=1`、自动评分 `ScoreRecord=0`（客观测验由 Attempt 保存总分，不创建教师评分记录）；重复提交未增加答案/事件 | 截止与刷新恢复通过；浏览器截图调用曾挂起，功能阶段及 API 已完成，后已为截图加 8 秒超时 |
| 提交事务完成但浏览器响应丢失 | CDP `Fetch` 在服务端响应阶段拦截 HTTP 200 后以 `ConnectionReset` 丢弃；这是**浏览器层模拟响应丢失**，不是物理网卡断开 | 页面显示未确认/失败；随后 result GET HTTP 200，点击重试显示结果；重复 POST 返回 `idempotent_replay=true` | Attempt `01M435Y0364C44R5PPSFBZ4RBK` 为 `graded`；答案行 `1`、提交事件 `1`、ScoreRecord `0`；提交重放没有追加副作用 | 模拟响应丢失通过；不能等同于真实网络设备故障 |
| Celery Worker 在隐私删除事务中终止 | 真实 Worker 的 `hold_privacy_after_delete` 在删除函数返回、工作事务提交前写标记并挂起；Worker 进程随后被终止，独立 Worker 重连相同 Redis broker | 故障 Worker 收到任务 `1ec74c4a-d613-4ee3-9ec8-c5a02ac27fb9`；恢复 Worker 收到**同一个 task ID** 并成功，状态 `completed_with_retention` | 同一任务重投后只完成一次删除工作单；完成响应 `attempt_count=1`；合成用户最终被禁用/删除，处理计数见下方日志摘录 | 真实进程终止与 broker 重投通过；与 pytest/in-process 结果分开 |
| 独立 Redis 暂不可用 | 对 C 专属 Redis TCP 服务做真实服务中断，协调标记确认停服窗口后发出删除请求，再恢复服务 | API 返回 HTTP 503 / `PRIVACY_DELETE_RETRYABLE`；Redis 恢复后登录成功 | 请求期间 `user_active=true`、`deletion_request_absent=true`，未产生半成品删除记录；无凭证进入日志 | 真实 Redis 故障及无副作用恢复通过 |
| 隐私删除经真实 broker/Worker 和重试 | 专属 Redis broker/result、真实 API 和 Worker；先挂起后终止，再观察原 task ID 重投；另做 Redis 恢复后的正常完成/重复状态重放 | 状态从未错误报告为完成；恢复后状态 `completed_with_retention`，完成后再次 retry 为幂等回放 | 代表性工作单处理计数：sessions 18、turns 4、chat_sessions 3、learning qualification/event/evidence/mastery 各 6、course_memberships 11；没有重复副作用或凭证明文日志 | 真实 broker/Worker 路径通过；删除/重试实现位于主窗口 `memory/`、Celery/core，不在 R2-C 修改范围 |

## 可复现命令

在 PowerShell 仓库根目录执行。专属 API/Redis/Worker/浏览器需先按 `docs/v1/V1并行启动状态.md` 指向 C 的独立配置，不能改用默认测试库或共享 Redis：

```powershell
$env:DATABASE_URL = 'postgresql+asyncpg://psychology:change-me@127.0.0.1:5432/psychology_learning_v1_r2_c_e2e'
$env:REDIS_URL = 'redis://127.0.0.1:6381/14'
$env:TASK_BACKEND = 'celery'
$env:CELERY_BROKER_URL = 'redis://127.0.0.1:6381/1'
$env:CELERY_RESULT_BACKEND = 'redis://127.0.0.1:6381/2'
$env:MINIO_BUCKET = 'v1-r2-c'
$env:PYTHONPATH = 'server/.venv/Lib/site-packages;server;scripts/r2_c'

# 真实 Tutor TCP 故障各运行一轮：启动 scripts/r2_c/tutor_fault_api.py，分别设为
# after_first_delta / after_commit_before_done，再运行以下客户端：
$env:R2_C_TUTOR_FAULT_MODE = 'after_first_delta' # 第二轮改 after_commit_before_done
$env:R2_C_FAULT_MARKER = (Join-Path $env:TEMP 'psychology-r2-c\r2-c-after-first-delta-20261004.marker')
# 专属 API 控制台运行，确认 marker 与客户端完成后只停止这个 fault API 进程：
F:\python.exe -m scripts.r2_c.tutor_fault_api
# 另一专属控制台等待 API 就绪后运行：
F:\python.exe -m scripts.r2_c.tutor_tcp_probe

# 浏览器测评：先用 scripts/r2_c/assessment_setup.py 生成一套新的课程、发布测验和 Attempt，
# 将输出 ID 设为下列变量后运行 scripts：
$env:R2_C_COURSE_ID = '<course_id>'
$env:R2_C_ASSESSMENT_ID = '<assessment_id>'
$env:R2_C_ATTEMPT_ID = '<attempt_id>'
$env:R2_C_QUESTION_VERSION_ID = '<question_version_id>'
$env:R2_C_ASSESSMENT_STUDENT_EMAIL = 'r2-c-assessment-student-b@example.com'
node web/tests/r2-c-assessment-browser.mjs
node web/tests/r2-c-assessment-submit-loss.mjs
node web/tests/r2-c-assessment-closed-recovery.mjs
```

Redis outage 与 Worker 终止须先启动唯一的 C 专属 fault Worker/协调探针，再按 `scripts/r2_c/redis_outage_probe.py` 与 `scripts/r2_c/privacy_recovery_probe.py` 执行；运行参数只从临时环境注入，不能把 256-bit 状态凭证写入命令历史或报告。Worker 终止场景使用 `R2_C_WORKER_FAULT_MODE=hold_privacy_after_delete` 和唯一 `R2_C_FAULT_MARKER` 启动 `F:\python.exe -m scripts.r2_c.worker_fault_entry`；只在 fault marker 出现后终止该 Worker PID，再将模式改为 `none` 启动同 broker Worker，并确认同一 Celery task ID 完成。探针不要与已有 Worker 并行消费同一队列。
