### 服务端证据

- 发布测验：隔离 API `POST /api/v1/assessments/{assessment_id}/publish` 返回 200。
- 首标签保存：`PUT /api/v1/attempts/{attempt_id}/answers/{question_version_id}` 返回 200，答案版本推进到 2。
- 旧版本写入：同一接口返回 409，错误码 `RESOURCE_VERSION_CONFLICT`，详情包含 `expected_version=1`、`actual_version=2`。
- 截止后写入：返回 409 `ASSESSMENT_CLOSED`。
- 提交后写入：返回 409 `ATTEMPT_SUBMITTED`。
- 待评分结果：`GET /api/v1/attempts/{attempt_id}/result` 返回 `score=null`、`grading_status=pending_teacher`、各题 `points_earned=null`。
- 覆盖发布后：结果返回 `status=graded`、`score=2`、`max_score=2`、`score_version=2`；旧决定仍留在评分历史中。
- SSE 弱网：离线请求产生真实 Chromium `net::ERR_INTERNET_DISCONNECTED`；恢复重试后服务端聊天记录只包含成功回合，但页面保留失败问题并重复显示重试问题，失败提示持续存在，存在 UI/服务端对话状态分歧。SSE 使用本地确定性 `model_gateway`，未调用外部模型；材料夹具没有正文，页面按证据不足明确拒答。

## 验收结论与未通过项

首轮隔离浏览器实测中，后端保存、乐观锁、截止/提交锁、待评分隐私、教师评分与理由覆盖均有浏览器或真实本地 API 证据；首轮发现刷新恢复、论述输入、创建后刷新和 SSE 重试 UI 缺口。它们的代码补丁和覆盖范围有限的第二轮复验记录在本文件后续章节。**P10-02 仍不能标记全通过**：已用浏览器模拟验证收到部分 delta 后 EOF 会回滚半截回答并恢复输入，但真实服务端传输中断及 Worker/Redis 恢复尚未测试；真实班级/教材及教学效果也不在本地隔离浏览器的证据范围内。

原有 API 8000 与当前工作区不一致，故关键浏览器路径改用独立 API 8001 和隔离数据库验证，没有重启 Web/Worker。窗口 C 的浏览器验收已执行并如实记录失败项；但 P10-02 总门槛仍未完成，除上述 UI 缺陷外，Worker/Redis 恢复和 SSE 已建立流中途断开也尚未验证。全流程使用自编题目和临时用户，不支持真实班级或真实学习效果结论。没有保存视频；本节列出的 PNG 为失败/关键状态截图。API 运行日志位于 `docs/v1/p10-02-artifacts/`。

## 复验前补丁记录（2026-10-03）

首轮浏览器验收后，代码侧已针对以下现象补充修复：

- 进行中测验列表仅返回当前学生自己的 `current_attempt_id`；刷新后学生练习页独立加载测验与复习任务，并自动恢复本人进行中的作答。教师及同课程其他学生均不得获得该 Attempt ID。
- 学生练习页增加 short-answer/essay 文本输入与防抖保存；恢复时读取已保存文本、答案版本和标记状态。
- 教师课程成员、题库、测验、教学观察、干预和 TeachingAsset 等异步提交处理器先保存表单节点，再等待 API；避免 React 事件结束后读取已清理的 `event.currentTarget`，从而出现“服务端已创建、前端却提示失败”并跳过刷新。
- 教材问答 SSE 失败时撤回未完成的本地临时问答对、将问题放回输入框并清除旧错误提示，用户重试不会在对话中留下重复问题。

补丁通过测评可靠性 API 测试（包括不同学生间 Attempt ID 隔离）、Web 10 项 Node 测试、TypeScript 和全仓 ESLint（0 errors、3 warnings）。随后进行的可见浏览器复验结果见下节；真实服务端传输中断与 Worker/Redis 恢复仍未验证。

## 补丁后浏览器复验（2026-10-03）

- 使用 Chromium 149、现有 Playwright 1.61，在 Web `http://127.0.0.1:3000` 上复验；浏览器的 `/api/v1` 流量临时转发到当前工作区 API `127.0.0.1:8001`，后端连接标准自动化测试库 `psychology_learning_test`，Redis 使用 DB 15、`TASK_BACKEND=in_process`。数据仅为演示账号和临时合成题目/测验，不涉及原演示数据库。
- 教师端：创建题目后草稿立即出现在题库列表、创建表单收起且无错误提示；添加临时学生后成员立即出现在列表；创建并发布测验后测验立即出现在列表。相应写接口均返回 201/200，写后刷新 GET 返回 200。
- 学生端：开始单选测验、作答保存后刷新页面，页面自动恢复同一 Attempt 和已选答案。进行中时复习列表接口按考试隔离策略返回 403，但测验列表仍独立成功并自动恢复，确认 `Promise.allSettled` 没有让复习权限失败遮蔽测验恢复。
- essay 测验中，文字输入框真实渲染；填写文本后出现“已保存”；刷新后同一文本和 Attempt 被恢复。测验数据仅在测试数据库中。
- SSE 补丁用可控浏览器网络路由复验：先成功发送一轮，再让第二轮请求以 Chromium offline 失败；失败时临时问答对从列表撤回、问题返回输入框、错误提示出现；恢复网络重试后第二轮问题只显示一次，回答正常出现，输入与旧错误提示清空。该轮用 mock 材料列表和 mock Chat/SSE 响应，只验 UI 状态恢复；服务端失败请求不留回合的证据仍来自首轮真实 API 测试。没有测试已建立 SSE 流中途断开、Worker/Redis 失败恢复。
- 本轮确认了首轮缺口中的教师建题/加成员/建测验刷新、学生测验刷新恢复、essay 保存恢复和请求发送前断网重试状态。后续模拟 SSE 流只发送部分 delta 后正常 EOF，确认前端拒绝不完整回合、移除半截 UI 内容并恢复问题输入；该模拟不等于真实 Socket/服务端断连。P10-02 仍未全部通过，真实传输断开与 Worker/Redis 故障恢复未验。
- 后续对 P7-04 独立测评壳进行 Chromium 交互验证：实际学生 Cookie 登录和正式测评路由使用当前 Web/API，课程、题目、Attempt 与答案写入响应由 Playwright 临时拦截提供；多选连续勾选两项分别提交 `selected_keys: ["A"]`、`["A", "B"]` 且 `answer_version` 顺序递增，判断“否”提交布尔值 `false`。无页面脚本错误，也未写入数据库；此为 UI/请求合同验证，不替代真实后端跨角色测评 E2E。
