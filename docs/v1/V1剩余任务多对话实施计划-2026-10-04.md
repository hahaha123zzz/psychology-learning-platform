### 5.2 前端代理和构建隔离

当前 `web/next.config.ts` 的 `/api` rewrite 固定指向 `http://127.0.0.1:8000`。独立 Web 端口不会自动使请求转发到独立 API。

主对话先处理并验证以下公共前置能力：

1. 增加可配置 API 代理目标，默认仍为现有 8000。建议环境变量 `PSYCHOLOGY_API_PROXY_TARGET`；这是拟新增能力，不能在实现前假设该变量已经生效。
2. 增加独立 Next 构建/开发输出目录配置。建议环境变量 `PSYCHOLOGY_NEXT_DIST_DIR`，各窗口使用独立目录；启动前确认 Next 16 对配置的实际支持。
3. 浏览器访问每个窗口的 `/api/v1/health/ready`，通过窗口标记或专属种子资源核对目标数据库，不能只凭 HTTP 200 判断连对环境。

### 5.3 pytest 与真实 Celery 的区别

当前 `server/tests/conftest.py` 在导入时将 `TASK_BACKEND` 固定为 `in_process`。只在运行 pytest 前设置 `TASK_BACKEND=celery` 不会取得真实 broker/Worker 验收证据。

R2-C 应提供独立的进程级验收入口，显式设置 `DATABASE_URL`、`REDIS_URL`、`CELERY_BROKER_URL`、`CELERY_RESULT_BACKEND` 和 `TASK_BACKEND=celery`，启动真实 API/Worker 后经 HTTP 和数据库状态断言验证。入口不得复用会改写运行环境或截表的公共 pytest client 夹具。

需要复用 pytest 编排时，先由主对话建立明确隔离的运行方式，不能删除公共夹具的保护规则来让测试“通过”。

| A6 | Reader 浏览器验收 | 实际页面显示与引用框一致；缩放/旋转/刷新可核对；键盘与窄屏可用；撤权后重新请求拒绝；解释页面定位精度限制 |

优先使用已指定 `TEXTBOOK/` 教材建立实际转换、构建和人工定位金标，金标保留原文件/转换版本、来源对象、页码、区域和判定依据；缺少的结构和明确失败边界再用自编 fixture 补测。自动测试与实际渲染/人工抽检分别报告。没有本地渲染器时，可交付 adapter/明确阻塞能力，但 A1/A2 的实际转换和渲染验收保持未通过，不能把“目录存在”记为构建成功。

复用已有 OOXML parser、PyMuPDF PDF 渲染、PageTransform 和不可变资产键。不要重写现有 PDF 页图路径。新增渲染工具的来源、许可证、实际复用范围与版本固定方式写入窗口报告，由主对话同步 `source-ledger.md`。

## 9. R2-C：真实故障恢复与隐私任务验收

### 9.1 故障矩阵

| 场景 | 复现方式 | 必须观察的结果 |
|---|---|---|
| SSE 建流前失败 | 独立浏览器网络阻断 | 输入保留，未成功回合不写证据/记忆，重试不重复显示 |
| SSE delta 中途 TCP 断开 | 独立 API/代理中断真实连接 | 关闭生成端；半回合不确认成功；前端回滚或明确未保存；重试使用同一请求 ID |
| SSE 已保存但 done 丢失 | 在提交后、完成事件到达前切断连接 | 同 ID/同正文重放已保存结果，业务副作用只有一次；同 ID/不同正文冲突 |
| 测评 autosave 离线/并发 | 独立浏览器离线、双标签/重复请求 | 保存失败不显示成功；恢复遵守答案版本；不静默覆盖服务端新版本 |
| 截止到达/页面关闭 | 服务端时钟/实际截止及关闭页面 | 只接受截止前服务端已持久答案；自动封存或提交语义明确；离线待发送答案不绕过截止；重入读取权威结果 |
| 提交响应丢失 | 提交已提交事务后断连 | 重试返回同一提交/成绩状态；无重复评分、事件或证据 |
| Worker 执行中终止 | 终止 R2-C 自有 Worker | 任务恢复到可解释状态；重投/受控重试可继续；没有重复发布或学习证据；失败不覆盖较新成功状态 |
| Redis/broker 暂不可用 | 停止并恢复 R2-C 独立 Redis | 请求/派发结果明确；恢复和重试有实际证据；模糊投递结果不产生重复业务效果 |
| 隐私删除真实排队 | 独立 API 经 broker 派发至真实 Worker | 新任务注册有效；受理后撤销会话；queued/failed/完成状态真实；完成后个人数据范围及保留类别可核对 |
| 隐私删除崩溃与重试 | 在工作事务/确认阶段终止自有 Worker | 原子回滚或已提交完成可判定；重复投递无重复副作用；凭预先保存凭证可无登录查询/重派发 |

状态断言同时检查 HTTP/SSE、页面显示和数据库的实际业务记录；不能只根据 Celery result、日志中的“success”或页面提示判断完成。

### 9.2 故障实验记录

每个场景保存：测试基线、独立环境配置摘要、故障发生点、请求/任务 ID、故障前后状态、重试结果、重复副作用计数、浏览器 trace/必要截图，以及失败或未运行事项。输出中不保存密码、Cookie、状态凭证、完整敏感 Prompt 或真实学生内容。

Celery 在 Windows 下选择并记录实际支持的运行模式，或使用独立容器 Worker。模拟函数失败、ASGI iterator close 和真实进程/TCP 实验分别列结果，不能互相替代。

### 9.3 修复及文件交接

SSE 与测评模块内的已复现缺陷由 C 在交接范围内修复；Memory/Celery/core 的缺陷提交给主对话，附可复现用例和建议状态语义。需要独占修改共享文件时先记录交接，修复后交回。

隐私保留政策缺失不通过自行物理删除正式答卷或审计来解决。验收报告明确 completed_with_retention 的实际含义。
