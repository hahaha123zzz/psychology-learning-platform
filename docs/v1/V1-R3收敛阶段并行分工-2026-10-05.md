## 3. 安全测试库交接

1. 主窗口只读核验 C/G 原库名称、revision、业务行数和活动连接；原库的数据、bucket 与截图均保留。
2. 主窗口为 C 与 G 各准备一座新的、此前不存在的独立空 PostgreSQL 测试库。建议候选名分别为 `psychology_learning_v1_r3_c_pytest_20261005` 与 `psychology_learning_v1_r3_g_pytest_20261005`；创建前检查名称未被占用，记录实际使用名、0051 revision、无业务行和连接数。迁移只由主窗口执行。
3. C/G 报告明确设置 `PSYCHOLOGY_TEST_DB`、`DATABASE_URL`、各自 `PSYCHOLOGY_TEST_REDIS_URL`、MinIO bucket 和 queue 后才能运行会调用 teardown `TRUNCATE ... CASCADE` 的 pytest。先确认目标库是新空库，不能把原 C/G 业务库、root 库、默认测试库或主预览库作为替代。
4. 测试后记录 revision、行数与资源使用情况；不删除数据库、数据或用户文件。若 fixture 仍指向错误库，停止该测试并交主窗口修正公共配置。

1. **立即可做：** B 在现有 0051 GO 内完成 SSE/Claim 接线；F 复核 8215 后完成真实只读浏览器；G 完成不清表的合同检查。主窗口并行准备 C/G 空库，检查 F API 与跨模块发布测试。C 可继续静态/Node 或不清表的浏览器准备。

3. **统一冻结：** 主窗口记录每窗最后写入时间与文件清单，要求受影响窗口停止写入；获取连续共同指纹。随后执行全后端、Alembic、OpenAPI、前端完整检查和独立 build。对失败文件只交唯一所有者修复，修复后重跑失效门槛。
