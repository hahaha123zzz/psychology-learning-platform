# V1 并行实施分工

更新时间：2026-10-04  
适用范围：当前已获授权的 V1 本地实施与验证；最终状态以代码、`implementation-status.md` 和 `acceptance-report.md` 为准。

## 1. 当前基线与分工原则

当前工作树已包含 V1 多阶段实现，最新迁移为 `0044_privacy_deletion_status_credential.py`，OpenAPI 为 125 paths。课程 Scope、学习事件与资格化、可恢复学习任务、正式测评、干预、Mini Lab、TeachingAsset、管理员治理和隐私删除均已有首批切片；它们不等于整项 V1 验收。优先并行处理剩余工作中可以独立交付的部分。

仓库有大量未提交改动。直接从现有 `HEAD` 创建新 worktree，可能缺少这些 V1 代码。各窗口开始前先由主窗口确定共同代码基线；在基线未固化前，使用同一工作树时必须严格遵守下表的文件所有权。任何窗口都不得重置、清理或覆盖其他窗口的改动。

| 窗口 | 负责人范围 | 主要交付 | 排他文件/目录 | 预计依赖 |
|---|---|---|---|---|
| 主窗口 | 集成与最终验收 | 共享迁移、OpenAPI、跨模块契约、总回归、状态报告 | `server/app/db/models.py`、`server/alembic/versions/`、`server/tests/conftest.py`、`contracts/openapi.json`、`AGENTS.md`、`docs/v1/implementation-status.md`、`docs/v1/acceptance-report.md` | 汇总所有窗口 |
| 窗口 A | P2 教材构建与页级 Reader | 固定版面资产、页级定位/高亮、引用重新鉴权、阅读 UI | `server/app/modules/materials/`、`server/app/modules/knowledge/`、新 Reader 模块与组件、对应专属测试 | 需要主窗口处理公共模型/迁移 |
| 窗口 B | P7/P10 测评与故障恢复 | 自动提交、已建立 SSE 流中断、Worker/Redis 故障的可复现恢复测试与修复 | `server/app/modules/assessments/`、`server/app/modules/tutor/`、`web/components/StudentAssessments.tsx`、`web/lib/sse.ts`、对应专属测试 | 不得占用预览服务及共享测试库 |
| 窗口 C | P9 治理工作台 | 完整 IAM/课程班级治理缺口、受控任务恢复 UI 与权限回归 | `web/app/admin/`、`web/components/Admin*`、`web/lib/admin-api.ts`、新增专属服务/测试 | 旧管理员路由位于 `memory/router.py`，由主窗口协调修改时段 |
| 窗口 D（可选） | P8 教学资产与 Mini Lab | 课程 Release 资产绑定、教材支持的实验定义和跨设备交互 | `server/app/modules/labs/`、`server/app/modules/teaching_assets/`、对应 Web 组件与测试 | 最终 2—3 个教材实验依赖可用且获准的本地教材来源 |

窗口 A、B、C 只有在主窗口发布共同代码基线与当前文件所有权清单后才能并行修改。此前只允许只读调研和形成待实施清单，不得直接改共享工作树。窗口 C 的管理员后端还需等待主窗口明确释放 `server/app/modules/memory/router.py`；窗口 D 只在来源、实验选题和使用边界明确时制作最终教材内容，否则先交付通用编辑与校验能力，并明确仍是工程 fixture。

### 启动条件

1. 主窗口先完成当前正在进行的编辑与验证，列出正在占用的文件、预览进程、测试数据库，并确认新窗口使用的共同 V1 代码基线。当前大量未提交改动必须包含在基线中，不能让新 worktree 直接从旧 `HEAD` 开始实施。
2. 主窗口逐一确认 A/B/C/D 的排他文件所有权；窗口收到确认后才能修改。主窗口在交付期间也不编辑这些排他文件。未获确认的窗口只做只读检查。
3. 需要跨窗口文件、公共模型、迁移或路由注册时，窗口先提交具体变更需求，由主窗口安排独占修改时段或统一集成；不得自行同时抢写。
4. 每个窗口在运行会写数据库的测试前，先确认自己的 `PSYCHOLOGY_TEST_DB` 和端口；不得占用在线预览库或其他窗口的测试库。

## 2. 各窗口交付条件

### 窗口 A：教材页面与证据定位

- 从现有 `EvidencePointer`、教材版本、来源对象和 bbox 合同出发，实现固定 PDF 页面资产与真实页级 Reader；DOCX 若无法可靠恢复页码/坐标，应给出明确降级，不伪造 bbox。
- 读者打开引用时重新检查当前课程 Scope、资料发布/归档状态与版本；权限失效返回 404。页码、高亮和摘录应指向同一不可变教材版本。
- 提供合成 PDF/DOCX 的定位回归、旧版本和撤权测试，以及浏览器中可复现的页级定位证据。视觉对象或精确坐标达不到门槛时据实标注，不把文本摘录面板当作页级 Reader。
- 不调用外部模型处理教材正文、图像或表格；OpenStax 材料只用于获准的本地离线对照。

### 窗口 B：测评与运行故障恢复

- 先复现已建立 SSE 流中途断开、请求重试、Worker 终止及 Redis 临时不可用，记录服务端持久状态和浏览器实际表现；再修复可证实的问题。
- 逐题答案、标记、提交、人工评分和 Tutor 回合不得因重试重复写入。截止时间与已提交状态以服务端裁决；自动提交要覆盖离线、关闭页面和并发标签页的明确语义。
- 新增独立测试数据库上的后端回归及可复现浏览器 E2E。前端仅收到服务端 `done/saved=true` 才标记回合完成；测试不能只检查文案。
- 保持考试期 AI 支持的 fail-closed 边界；尚无受限执行器时不能宣称 `direction_only` 可用。

### 窗口 C：管理员治理

- 在现有同机构角色授予/撤销、班级任课、教材任务受控重试基础上补完整管理流程；管理员身份不能隐式获得课程正文或学生私聊访问权。
- 对每个写操作固定同机构/课程/班级 Scope、理由、幂等、乐观锁冲突和审计；跨机构与无权资源统一避免枚举。列表只返回管理所需的最小字段。
- 管理员页面使用真实 API 与状态，不用静态样例冒充处理结果；补越权、重复提交、并发冲突和失败恢复回归。
- 涉及 `server/app/modules/memory/router.py`、`auth/router.py` 或 `courses/router.py` 时先取得主窗口的文件所有权，完成后及时交还。

### 窗口 D：TeachingAsset、Release 与 Mini Lab

- 补齐 TeachingAsset 在已发布 CourseRelease 下的呈现、版本与回退；未知资产类型应安全降级为文本。正式教材资产需保留来源、版本和审核状态。
- 将 Mini Lab 六阶段检查点能力与 2—3 个获准教材实验定义绑定；预测、原始 TrialData、解释和学习证据继续分轨。反应时或单次正确不直接变成掌握结论。
- 没有明确教材来源或许可时，只完成编辑/校验/恢复能力并保留自编 fixture 标识，不把它表述成最终教材实验或科研效度验收。

## 3. 共享资源与交接规则

1. 每个窗口先阅读 `AGENTS.md`、V1 总体执行计划、`implementation-status.md` 及负责模块的 router/service/model/测试，并检查 `git status`。已有改动均视为他人工作成果。
2. `models.py`、Alembic 线、OpenAPI 快照、根配置、`tests/conftest.py` 和总状态文档由主窗口单独修改。其他窗口需要公共字段或新迁移时，提交字段、约束、回填及测试要求给主窗口；主窗口按单一线性迁移链落地。
3. 各窗口使用独立测试数据库：A 用 `psychology_learning_v1_window_a`，B 用 `psychology_learning_v1_window_b`，C 用 `psychology_learning_v1_window_c`，D 用 `psychology_learning_v1_window_d`，并分别设置 `PSYCHOLOGY_TEST_DB`。禁止同时使用默认 `psychology_learning_test` 跑会截表的测试。
4. Web 3000/API 8000 的预览进程由主窗口管理。其他窗口不得重启、改用原演示数据库或运行会覆盖当前 `.next` 的构建；需要浏览器验收时使用独立端口和隔离数据库。
5. 每个窗口交付时提供：改动文件、接口/迁移需求、通过的命令与数量、失败或未运行的验证、截图/日志位置、尚存边界。状态报告区分已编码、自动测试、本地环境、真实教材/模型、真实班级和生产验证。
6. 主窗口按 A/B/C/D 完成顺序接收改动，解决共享契约冲突，统一生成 OpenAPI，执行 Alembic upgrade/check、全量后端回归和前端 test/typecheck/lint；浏览器关键路径再复验。只有代码、迁移、契约、测试和文档一致的项目才能在验收报告中标为完成。

## 4. 明确的范围边界

- 生产部署、监控告警、备份恢复、容量验证、真实班级试用和学习效果研究不属于当前已授权的本地实施范围；本地通过不得写成这些事项已完成。
- 真实教材、学生答案和敏感学习记录不得送往外部生成或 Embedding API，除非逐本许可、供应商处理承诺和用户授权均已明确。
- 现有 `docs/v1/并行实施窗口提示词.md` 记录的是较早阶段任务，其中若干窗口已完成；新窗口按本文及最新实施状态领取剩余任务，避免重复施工。
