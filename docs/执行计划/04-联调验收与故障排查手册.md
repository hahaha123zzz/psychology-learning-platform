# 联调验收与故障排查手册

## 1. 联调原则

联调不是把两个人代码都合并后“点一点页面”。每次联调必须固定代码版本、数据库迁移版本、OpenAPI版本、模型配置、教材版本和测试账号，并保留request_id、日志和结果。

联调顺序固定为：依赖健康 → 迁移 → 权限 → 数据准备 → 提供端接口 → 消费端契约 → 正常流程 → 异常流程 → 幂等/并发 → 监控与审计。

## 2. 联调环境准备

### 2.1 固定测试角色

- `admin_test`：系统配置，不默认加入课程。
- `teacher_a`：课程A教师。
- `teacher_b`：课程B教师，用于隔离测试。
- `student_a1`、`student_a2`：课程A学生。
- `student_b1`：课程B学生。
- `disabled_user`：停用账号。

### 2.2 固定测试数据

准备一份真实实验心理学教材、一份扫描质量差的PDF、一份损坏文件、一份重复文件和一个新版本教材。准备30个有标准证据的问题、5个资料外问题、10道教师题、20道生成候选题和至少两个测验策略。

### 2.3 启动前检查

1. Git提交号一致，工作区无未说明改动。
2. `.env`来自模板且无密钥进入仓库。
3. 数据库迁移只有一个head。
4. PostgreSQL、Redis、MinIO健康，磁盘空间足够。
5. OpenAPI文件与运行API一致，前端客户端已重新生成。
6. 模型网关、Embedding和Reranker配置用途正确。
7. 浏览器缓存和旧Service Worker已清理。

## 3. 五次强制集成验收

### G1：教材闭环（第3周）

执行：teacher_a创建课程并加入student_a1；上传正常教材；观察ParseJob；修正一个章节标题和图注；发布；student_a1登录阅读；student_b1用直链尝试访问。

通过：页数与源文件一致；章节可跳转；修正有版本；学生A可读；学生B返回404；损坏文件失败且可重试；重复上传有提示。

常见失败：解析完成但前端一直running，先检查任务状态是否事务提交，再查轮询缓存；学生B能打开预签名地址，说明签名签发或对象权限绕过了应用校验。

### G2：可信问答（第5周）

执行：运行30个教材问题和5个资料外问题；检查Evidence、引用页、高亮、回答claim；中途断开SSE；移除student_a1课程权限后重开旧引用。

通过：正确证据达到基线；关键claim有支持；资料外问题拒答；旧引用权限失效；断流不写完整turn和记忆；同问多次核心证据稳定。

常见失败：有引用但不支持答案，定位到claim—citation映射而不是继续调top_k；查询词被显示为来源，检查fallback数据是否错误进入citation事件。

### G3：学习闭环（第7周）

执行：教师录题和生成候选题；审核发布；建立练习和正式测验；学生练习中使用教练、创建分支并merge；正式测验尝试直接调用教练接口；完成错题复习。

通过：候选题不能自动发布；正式测验后端拒绝教练；自动保存不丢；分支不污染主摘要；merge幂等；错题产生可解释复习任务。

### G4：上线准备（第9周）

执行：从空服务器部署；导入测试数据；完成完整E2E；制造模型超时、Redis短暂不可用和Worker重启；备份后在隔离环境恢复。

通过：内部端口不公开；故障有可读提示；权威数据不依赖Redis；任务可恢复；备份校验和正确；恢复后引用、作答和统计一致。

### G5：班级试用（第10周）

执行：发布固定RC；教师按脚本建课；3个测试学生完成任务；观察监控；演练回滚；确认数据说明和反馈入口。

通过：P0/P1为零；核心错误有request_id；费用和延迟在预算；回滚不降级数据库；教师签字确认课程内容。

## 4. 分层排查方法

### 4.1 页面打不开或数据为空

1. 浏览器Network确认请求是否发出、路径和状态码。
2. 核对当前账号、课程成员和Cookie是否有效。
3. 用request_id查API日志，不先猜前端问题。
4. 检查API响应是否为空还是前端解析失败。
5. 检查OpenAPI客户端版本和字段枚举。
6. 检查数据库是否存在当前课程且状态已发布。

禁止做法：遇到403临时关闭权限；遇到空数据在前端写假数据；直接改数据库状态不补迁移或业务记录。

### 4.2 上传失败

1. 检查大小、MIME、文件签名和课程配额。
2. 检查MinIO连接、桶、凭据和磁盘。
3. 查MaterialVersion状态和对象键。
4. 若对象存在而数据库失败，确认补偿任务是否处理。
5. 相同Idempotency-Key检查请求body是否一致。

### 4.3 解析卡住

1. 从Job查看stage和最后心跳。
2. 检查Worker是否消费正确队列。
3. 检查源文件能否下载且哈希一致。
4. 检查解析器进程、超时、内存和临时磁盘。
5. 检查结果规范化是否因单页异常阻塞。
6. 超时后从检查点重试，不直接把状态改success。

易错判断：进度99%不代表解析器问题，可能是持久化或质量检查失败；Worker重启后任务仍running说明缺少租约/心跳过期处理。

### 4.4 检索不到正确内容

1. 确认教材版本已发布且索引ready。
2. 在解析对象中确认正确原文确实存在。
3. 检查分块是否将条件和结论拆散。
4. 分别运行BM25和向量召回，定位是哪一路丢失。
5. 检查权限、章节、对象类型和过期过滤。
6. 查看RRF和Reranker前后排名。
7. 只在评测集上调整参数并记录版本，禁止为单题硬编码。

### 4.5 引用打不开或定位错误

1. evidence_id是否绑定正确version_id。
2. 当前用户是否仍有课程权限。
3. preview_url是否过期，前端是否错误缓存。
4. physical_page与printed_page是否混用。
5. bbox是否基于相同页面尺寸、旋转方向和坐标原点。
6. 教师修正后旧Evidence是否仍指向可追溯版本。

### 4.6 SSE不流式或重复消息

1. 检查响应Content-Type和代理缓冲。
2. 检查Nginx是否设置适合SSE的超时与buffering。
3. 检查事件是否包含turn_id和sequence。
4. 检查客户端是否重复注册监听器。
5. 检查断线重连是否从已确认sequence继续。
6. 检查用户取消后服务端是否停止模型调用。

### 4.7 教学流程卡住或复读

1. 查LearningSession当前state、version和允许动作。
2. 查最近动作指纹和循环计数。
3. 检查模型返回动作是否被Schema验证拒绝。
4. 检查前端是否未提交学生response而重复请求提示。
5. 检查同一请求是否因重试执行两次状态转移。
6. 达阈值后必须进入降级或人工帮助，不能只继续调Prompt。

### 4.8 自动保存覆盖答案

1. 比较客户端answer_version、服务端version和请求完成顺序。
2. 查多个标签页是否同时编辑。
3. 检查防抖任务是否在切题后仍提交旧内容。
4. 409时保留双方内容，让用户选择，禁止静默最后写入获胜。

### 4.9 记忆或画像明显错误

1. 查看条目layer、来源Evidence和confidence。
2. 确认是“学生问过”还是“学生答错”的事件类型。
3. 检查是否只有一次证据却升到L3。
4. 检查冲突条目是否错误覆盖而非supersede。
5. 检查摘要是否丢失否定或条件。
6. 先标记待复核/降低置信度，再重算画像；不要直接修改显示文本掩盖底层错误。

### 4.10 统计不一致

1. 明确统计口径、时间范围、时区和更新时间。
2. 从聚合结果回查原始事件数量。
3. 检查event_id去重、迟到事件和重放。
4. 检查分母是否含未开始学生或已退课学生。
5. 检查教材/题目版本是否混合。
6. 重算时记录聚合版本，不能无记录覆盖旧报表。

### 4.11 权限漏洞

1. 用另一个课程账号替换URL中的ULID。
2. 替换body内course_id、material_id和student_id。
3. 重放旧签名URL和旧Cookie。
4. 检查批量接口中每个对象，而非只检查第一个。
5. 检查导出、预览、SSE、后台任务和错误详情是否同样执行权限。
6. 发现漏洞立即停用相关入口、保留审计、修复并增加回归测试。

## 5. 错误分级与响应

| 级别 | 定义 | 示例 | 处理时限 |
|---|---|---|---|
| P0 | 数据泄露、丢失、严重安全或全站不可用 | 跨课程访问、备份覆盖生产 | 立即停止相关服务并回滚 |
| P1 | 核心流程无法完成或答案大规模错误 | 无法登录、教材问答错误引用 | 当日修复，阻止发布 |
| P2 | 有替代路径但明显影响使用 | 部分图表定位错误 | 当前迭代处理 |
| P3 | 体验或低频问题 | 文案、轻微布局 | 进入后续清单 |

## 6. 发布前检查

### 6.1 代码与版本

- main无未提交改动，CI全绿。
- 镜像、迁移、OpenAPI、索引和配置版本已记录。
- 依赖锁文件与镜像一致。
- Feature flag状态已列明。

### 6.2 数据与安全

- 生产密钥来自安全配置，不在镜像和仓库。
- 管理员、教师、学生权限矩阵通过。
- 日志抽查无Cookie、Token、密码、密钥和完整敏感对话。
- 数据保存、纠正和删除路径可用。
- 测试账号与真实账号区分。

### 6.3 AI与知识质量

- 教材版本和索引ready。
- 30题RAG回归无明显退化。
- 资料外拒答、冲突来源和引用定位通过。
- 出题候选无自动发布路径。
- 教学循环检测和最大步数生效。

### 6.4 运维

- 最新备份有校验和且完成隔离恢复。
- 监控覆盖错误率、延迟、队列、数据库、对象存储、磁盘和模型费用。
- 域名、HTTPS和证书到期告警正常。
- 回滚步骤经过演练，值守联系人明确。

## 7. 回滚原则

应用回滚不自动回滚数据库。优先使用向后兼容迁移和feature flag关闭新功能。索引切换使用版本指针，可回到上一ready版本。若新版本已写入新格式数据，回滚前必须确认旧应用能忽略新字段或使用兼容读取层。

## 8. 验收记录模板

每次验收记录：日期、Git提交、环境、迁移版本、OpenAPI哈希、教材/索引版本、模型配置名称、执行人、用例、预期、实际、request_id、截图/日志位置、结论、问题级别、负责人和复验日期。

没有这些信息的“已测过”不能作为发布依据。
