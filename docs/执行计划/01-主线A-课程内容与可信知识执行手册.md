# 主线A执行手册：课程内容与可信知识

## 1. 主线目标与边界

A负责把教师资料变成“可管理、可检索、可验证、可发布”的课程资产，并为B提供稳定接口。A不负责学生教学状态、作答记忆和画像，也不得直接写入这些表。

A的完成标准：任何一条AI课程回答都能说明用了哪个课程、哪一版教材、哪一页或哪个对象；任何正式题目都能说明来源、答案、评分规则、审核人与版本；任何异步任务都能被查询、重试和审计。

## 2. 任务卡A01：后端与基础设施骨架（D1—D3，2.5人日）

### 前置条件

- 确认Python、Node、Docker版本。
- 确认开发端口和环境变量命名。
- 确认本地数据目录不进入Git。

### 执行步骤

1. 建立`server/main.py`和`/health/live`、`/health/ready`。
2. 建立配置类，区分development、test、production；缺少关键配置时启动失败。
3. Docker Compose只暴露Web入口；PostgreSQL、Redis、MinIO仅内部网络访问。
4. 建立SQLAlchemy会话、Alembic、事务依赖和统一异常处理中间件。
5. 建立结构化日志，至少包含request_id、trace_id、user_id哈希、route、status和latency。
6. 建立Celery连接、任务基类、最大重试次数和死信记录。
7. 在CI中运行Ruff、Pytest、迁移头检查、OpenAPI导出和敏感信息扫描。

### 易错点与排查

- 健康检查只返回进程存活，却不检查数据库：`live`只查进程，`ready`检查必要依赖，二者分开。
- 测试误连开发数据库：测试启动必须检查数据库名带`_test`，否则拒绝运行。
- 重试造成重复副作用：任务写入前检查业务幂等键，不能只依赖Celery task id。
- 日志打印完整请求体：默认禁止；只为安全字段建立白名单。
- 容器中使用`localhost`访问其他服务：必须使用Compose服务名。

### 验收

全新机器按README在30分钟内启动；停止数据库时`ready`失败但`live`仍成功；重复运行迁移不报错；日志不出现密码、Cookie和模型密钥。

## 3. 任务卡A02：认证、RBAC与课程成员（D2—D5，3.5人日）

### 数据与规则

`User`、`Course`、`Enrollment`使用ULID。课程成员角色只允许`teacher`、`assistant`、`student`。平台管理员不是课程教师，不能因为是管理员就默认读取私密课程内容。

### 执行步骤

1. 实现登录、刷新、退出和`/me`；会话使用HttpOnly、Secure、SameSite Cookie。
2. 建立`require_platform_role`、`require_course_member`、`require_course_role`三层权限依赖。
3. 课程查询始终从当前用户可见范围构造，不先查对象再判断，降低资源存在性泄露。
4. 修改课程和成员使用乐观锁`version`；冲突返回409。
5. 移除成员前检查是否是唯一教师；禁止把课程置于无人管理状态。
6. 对添加、移除、角色变更写入AuditLog。

### 易错点

- JWT或Cookie有效不代表有课程权限。
- 返回403和404时泄露“资源存在”：对无权资源统一按当前权限范围返回404。
- 只校验路由参数的course_id，未检查body内关联对象是否属于同一课程。
- 刷新令牌无限有效或无法撤销。
- 教师从课程移除后旧会话仍缓存权限；关键写操作必须实时校验。

### 验收用例

学生A不能读取学生B课程；教师A不能修改教师B课程；管理员进入课程内容需显式授权；被移除成员下一请求立即失效；猜测ULID无法侧漏标题。

## 4. 任务卡A03：教材上传与版本（D6—D10，5人日）

### 执行步骤

1. 上传前验证扩展名、MIME、大小、课程权限和配额；文件名只用于展示。
2. 计算SHA-256；对象键使用课程ID/资料ID/版本ID，不使用用户文件名。
3. 先创建`uploading`版本，再写对象；成功后转`uploaded`，失败转`failed`。
4. 相同课程相同哈希提示复用或建立引用，不能无提示重复占空间。
5. 新版本是新记录；旧版本保持不可变。发布指针只在事务内切换。
6. 删除采用归档/延迟清理。被题目、引用或测验使用的版本不能物理删除。
7. 下载和预览使用短期签名地址；签发前再次校验权限。

### 易错点

- 数据库提交成功但对象上传失败：使用补偿状态，定时扫描孤儿。
- 对象成功但数据库回滚：为对象打临时标签，清理无引用对象。
- Content-Type由用户任意指定：服务端检测并校验。
- 大文件经API进程完整读入内存：使用流式或预签名直传。
- 发布新版本后旧聊天引用跳到新页：Evidence必须绑定具体version_id。

### 验收

重复提交同一Idempotency-Key只产生一个版本；上传中断可重试；草稿对学生不可见；旧引用仍打开旧版本；删除失败不造成数据库和对象状态不一致。

## 5. 任务卡A04：解析与中间格式（D11—D15，5人日）

### 中间格式

每个对象至少包含`object_id`、`material_version_id`、`type`、`chapter_path`、`physical_page`、`printed_page`、`reading_order`、`bbox`、`raw_content`、`normalized_content`、`parser`、`parser_version`、`confidence`和`review_status`。

### 执行步骤

1. 为MinerU定义Adapter，不让业务层依赖其原始JSON。
2. 解析任务分为下载、渲染、解析、规范化、质量检查、持久化六个stage。
3. 每个stage写进度和错误码；超时后任务可从安全检查点继续。
4. 依据标题样式、编号和目录建立章节树；不能只靠字体大小。
5. 图、表、公式保存页面坐标，与图号、图注、相邻段建立关系。
6. 原始解析对象不可修改；教师修正创建override层和新版本。
7. 发布前执行质量门：空页比例、低置信度比例、无标题文档、表格错位抽样和页数一致性。

### 易错点与排查顺序

1. 页数不一致：先比较源PDF页数、渲染页数、解析页数。
2. 中文乱码：检查字体嵌入、OCR语言和文本编码，不直接替换异常字符。
3. 阅读顺序错：查看bbox和版面列，不以JSON数组顺序为准。
4. 图注错配：限定同页、距离、编号一致性，低置信度交给教师。
5. 表格串行：保留单元格行列坐标，不只保存Markdown文本。
6. 公式丢失：保存原图和LaTeX候选，未验证时不当精确公式检索。

### 验收

从教材抽取10页、3张图、2个表和2个公式人工对照；章节层级、页码和图注关系达到教师可接受；失败页不会进入已发布索引。

## 6. 任务卡A05：分块、索引与混合检索（D16—D20，5人日）

### 执行步骤

1. 优先按章节、标题、段落和对象边界分块，超长对象再语义切分。
2. 子块保留parent_id、前后对象和相关图表，不复制失去来源的纯文本。
3. 正文和标题建立全文索引；Embedding任务记录模型、维度、规范化和版本。
4. 查询先做权限范围和课程范围，再执行BM25和向量检索。
5. 采用RRF融合；初版参数写配置且纳入评测版本，不散落代码。
6. 对候选进行去重、过期过滤、章节范围过滤和top_k裁剪。
7. 建立调试响应，仅教师/管理员可看分数、引擎和过滤原因。

### 易错点

- 用固定500字切分破坏定义条件。
- 将页眉页脚重复内容索引成高频结果。
- 在全库检索后再做权限过滤。
- 改Embedding模型却继续使用旧向量。
- top_k过大导致模型上下文被噪声淹没。
- 测试只看“能搜到”，不看排序、稳定性和资料外问题。

### 验收

教师提供30个问题，每题标注正确证据；记录Recall@K、MRR、引用页和重复运行稳定性；资料外问题不能召回无关高分段落后强答。

## 7. 任务卡A06：Evidence Package与引用校验（D21—D25，5人日）

### 执行步骤

1. Reranker只处理已授权候选，并记录模型版本和原始分数。
2. 命中子块后按规则补父块、定义条件、图注和必要邻块。
3. 构建Evidence Package：来源、版本、章节、页码、锚点、原文、对象关系、授权和检索信息。
4. 给每项证据生成短期`evidence_id`，前端只能通过解析接口打开。
5. 模型输出结构包含回答段、claim和citation_ids。
6. 校验每个claim是否被引用原文支持，输出`supported`、`partial`、`conflict`或`not_found`。
7. `not_found`删除或改写为明确不知道；`conflict`并列展示版本并提示教师。

### 易错点

- 引用只指向资料首页。
- 引用段落存在，但不支持对应句子。
- 把模型生成的摘要作为证据再次循环引用。
- 临时签名地址过期后前端永久缓存。
- 认为校验模型一定正确；仍需规则和人工评测。

### 验收

抽检至少50条claim；每条能回到具体版本与页段；无权限后旧链接失效；查询词回显不能显示为引用；回答允许明确“教材未提供”。

## 8. 任务卡A07：题库、测验配置和出题Agent（D26—D35，8人日）

### 题目生命周期

`draft → review → approved → published → archived`。修改已发布题目必须创建新QuestionVersion。测验引用具体版本。

### 教师录题步骤

1. 录入题干、题型、选项、答案或rubric、解析和难度。
2. 绑定一个或多个Evidence；未绑定不能发布。
3. 服务端检查单选唯一答案、分值总和、空选项和版本冲突。
4. 审核人与创建人可以相同用于试点，但AuditLog必须记录。

### 出题Agent步骤

1. 覆盖规划：章节、知识点、题型、数量和难度分布。
2. 每题先检索证据，再生成题目，禁止先生成后硬找引用。
3. 独立生成答案、解析、评分点和难度理由。
4. 规则检查：字段完整、唯一可解、分值、敏感词和超纲。
5. 模型校验：答案是否被证据支持、干扰项是否合理。
6. 向量与规范化文本去重；相似题进入人工比较。
7. 全部结果进入`draft`，教师逐题通过、修改或驳回。

### 易错点

- 同一个模型同一次调用同时出题和自证正确。
- 多选题漏标答案数量或出现包含关系提示。
- 题目答案依赖教材外常识却标为教材题。
- 难度只由模型主观给出，没有任务特征说明。
- 删除旧题导致历史作答无法解释。
- 测验接口提前返回答案、评分点或解析。

### 验收

生成20道候选题，教师记录通过率和修改原因；正式发布题都有证据、版本和审核记录；学生接口在开放前后、提交前后返回内容符合规则。

## 9. 任务卡A08：模型网关、任务治理与安全（D36—D40，5人日）

### 执行步骤

1. LLM、Embedding、Reranker分配置；调用方传用途，不直接传任意模型地址。
2. 记录provider、model、purpose、latency、token、status和trace_id，不记录密钥。
3. 为问答、出题、摘要设置不同超时、并发、预算和重试策略。
4. 429/5xx只对安全请求退避重试；流式已输出内容不得自动重新扣费生成。
5. 管理健康页只显示脱敏状态，不回显完整Base URL密钥参数。
6. 文件上传、IDOR、SQL注入、提示注入和日志泄露执行专项测试。

### 易错点

- 所有模型调用共享同一超时。
- 失败重试没有幂等，生成多批题。
- 将用户文本拼入系统工具指令造成越权。
- 健康检查调用昂贵模型导致额外费用。
- 在异常堆栈中打印Authorization Header。

## 10. 任务卡A09：部署、监控、备份与恢复（D41—D50，7人日）

### 部署顺序

1. 构建固定版本镜像并生成依赖清单。
2. 在隔离环境运行数据库迁移和索引兼容检查。
3. 启动PostgreSQL、Redis、MinIO，再启动API/Worker/Web/Nginx。
4. 执行ready检查、迁移版本、对象桶、队列和模型网关检查。
5. B执行核心业务冒烟后才切换流量。

### 备份范围

PostgreSQL、MinIO对象、关键配置的脱敏副本、教材索引版本清单和应用镜像版本。Redis缓存通常不作为权威备份，但未处理任务要能从数据库恢复。

### 恢复演练

在新目录和隔离数据库恢复，核对备份校验和；启动后由B验证登录、教材、引用、测验、历史作答和统计。禁止第一次恢复直接覆盖生产。

### 易错点

- 数据库与对象存储备份时间点不一致。
- 备份成功日志存在但文件为零字节或不可解密。
- 回滚应用同时错误回滚数据库迁移。
- Nginx转发SSE启用缓冲，导致流式回答一次性出现。
- Worker与API使用不同配置或时区。
- 磁盘告警只看总盘，不看对象存储和数据库卷。

## 11. A向B的交付模板

每个接口交付必须提供：OpenAPI版本、curl或HTTP样例、测试课程ID、权限角色、正常响应、至少四种错误、幂等规则、版本/缓存规则、数据是否最终一致、监控位置和回滚方法。B确认消费测试通过后才算完成。

## 12. A的最终检查

- 所有教材对象可追溯到原文件哈希和版本。
- 所有引用能定位且权限变化后立即失效。
- 所有正式题目有证据、答案、审核和不可变版本。
- 所有异步任务有进度、失败、重试和幂等。
- 所有公共接口有契约测试和示例。
- 生产环境无数据库、Redis、MinIO管理端和FastAPI内部端口暴露。
- 备份在隔离环境恢复成功，B完成业务冒烟。
