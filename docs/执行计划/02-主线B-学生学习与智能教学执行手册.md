# 主线B执行手册：学生学习与智能教学

## 1. 主线目标与边界

B负责把A提供的课程、教材证据和题目组织为完整学习体验。B不自行解析教材、不复制RAG逻辑、不直接读取A内部表。任何教学结论使用A提供的Evidence；任何个性化结论必须有学习证据并可纠正。

## 2. 任务卡B01：Web骨架、会话和角色工作区（D1—D5，5人日）

### 执行步骤

1. 建立学生、教师、管理员路由组和统一布局；路由保护只改善体验，最终权限由API决定。
2. 从OpenAPI生成客户端，封装request_id、401刷新、409冲突和422字段错误。
3. 建立加载、空数据、无权限、服务失败、局部重试五种通用状态。
4. 登录后调用`/me`获得角色和课程，不从本地存储相信旧角色。
5. 建立错误边界、Toast规则和不泄露内部堆栈的错误页。
6. 建立Playwright冒烟：登录、角色跳转、课程列表、退出。

### 易错点

- 在LocalStorage保存长期Token。
- 401时多个并发请求同时刷新形成风暴；使用单飞刷新。
- 403统一显示“系统错误”，学生无法判断权限问题。
- 客户端缓存教师页面，退出后后退仍显示敏感数据。
- 手写接口类型与OpenAPI逐渐偏离。

### 验收

三种角色路由正确；会话过期只刷新一次；退出后敏感页面不可从缓存访问；网络失败保留重试入口。

## 3. 任务卡B02：学生课程空间与教材阅读（D6—D15，8人日）

### 页面组成

课程首页、章节目录、教材阅读页、最近学习、待完成测验、复习任务和进度摘要。首期不做信息密度过高的综合大屏。

### 执行步骤

1. 课程首页只展示已发布内容；草稿或处理中资料不生成空卡片。
2. 章节目录使用A的稳定章节ID，保存最近阅读对象而非页面滚动像素。
3. 阅读页支持页码、章节跳转、文字/图表定位和引用高亮。
4. 学习事件采用白名单并批量上报；客户端生成event_id用于去重。
5. 离线或弱网时事件进入有限本地队列，恢复后按原时间上传。
6. 阅读进度不以页面停留时间直接判定完成，至少结合滚动、活动和显式完成。
7. 移动端保留核心阅读和提问，不强行塞入桌面三栏布局。

### 易错点

- 页面打开就算完成。
- 浏览器后台标签仍累计学习时间。
- 同一事件重试多次造成统计膨胀。
- 教材版本更新后最近位置指向不存在对象；通过旧ID映射或回退章节。
- 直接公开MinIO永久地址。
- 高亮坐标没有考虑页面缩放与旋转。

### 验收

真实教材目录可跳转；刷新后恢复最近位置；重复事件不增加次数；移动端可完成阅读和提问；无权限链接不显示内容。

## 4. 任务卡B03：课程问答与SSE（D16—D20，5人日）

### 服务端流程

1. 验证用户、课程、会话和当前教材范围。
2. 写入学生turn并提交事务。
3. 调用A的检索接口取得Evidence Package。
4. 构建模型上下文，严格区分系统规则、教材证据、用户文本和记忆。
5. 以SSE发送state、delta、citation、action、usage、done或error。
6. 生成完成后保存AI turn、引用和调用记录；中断内容标为`partial`，不进入记忆。

### 前端流程

提交后立即显示用户消息和可取消状态；按delta追加；citation先占位再解析；手动停止后显示“已停止”，允许重新生成但产生新turn分支。

### 易错点

- 客户端断线后服务端继续生成并重复扣费；检测断开并设置取消。
- 重连重复消费SSE；事件带序号和turn_id。
- 用户快速双击发送；按钮禁用并使用Idempotency-Key。
- 模型错误后把错误消息写成AI正式回答。
- Markdown渲染允许危险HTML或javascript链接。
- 引用卡片只显示标题，不验证当前权限。

### 验收

弱网中断能明确恢复或重试；停止生成不会写记忆；引用按事件出现；多标签页不会重复提交；XSS测试通过。

## 5. 任务卡B04：AI教师状态机（D21—D25，5人日）

### 状态与动作

状态固定为`goal`、`diagnose`、`evaluate`、`hint`、`explain`、`practice`、`reflect`、`complete`、`paused`。允许动作由服务端表定义，模型只能建议动作。

### 执行步骤

1. 创建LearningSession，保存学习目标、知识点、状态、step、提示级别和版本。
2. `goal`确认目标；模糊目标只追问一个澄清问题。
3. `diagnose`提出一个问题并发送`wait_for_student`，不得在同一turn继续代答。
4. `evaluate`输出正确、部分正确、误区或无回答，附可解释理由。
5. `hint`按方向、关键线索、局部示例逐级增加；达到上限转`explain`。
6. `practice`要求复述、比较或迁移；`reflect`总结已掌握、待复习和证据。
7. 每次转移采用乐观锁，重复响应只生效一次。

### 循环检测

保存最近5次`state + action + knowledge_point + normalized_output`指纹。连续3次同状态同动作或相似度超过阈值时先换策略；仍重复则停止，提供查看教材、示例、暂停或教师帮助。

### 易错点

- 把整个流程写在Prompt里而没有后端状态。
- 模型输出不存在的状态导致崩溃；未知动作拒绝并记录。
- 同一回合问多个问题，无法判断学生理解。
- 学生说“不知道”被当成错误答案无限追问。
- 循环检测只做字符串完全相等，模型轻微改写即可绕过。
- 恢复会话时只加载聊天文本，不加载状态版本。

### 验收

覆盖所有合法转移和非法转移；刷新/退出/恢复状态一致；连续失败会降级策略；教师可查看状态轨迹但学生看不到内部Prompt。

## 6. 任务卡B05：测验作答与悬浮教练（D26—D30，5人日）

### 作答流程

1. 创建Attempt时由服务端冻结assessment规则和题目版本。
2. 每个答案PUT保存，携带answer_version；409时提示比较而非静默覆盖。
3. 客户端每次编辑防抖保存，同时显示最后成功时间。
4. 提交前服务端再次验证开放时间、身份、状态和必答规则。
5. 提交事务锁定Attempt，客观题规则评分；主观题进入待复核。
6. 结果页按教师设置决定何时显示分数、答案和解析。

### 悬浮教练

教练上下文只含题目版本、学生当前答案、已用提示、允许策略、关联知识点和Evidence。正式测验策略为`disabled`时后端直接403；`direction_only`只能给方向；练习模式才允许完整讲解。

### 易错点

- 前端倒计时为零但服务端仍允许提交或相反；服务端时间权威。
- 自动保存响应乱序覆盖新答案；使用answer_version。
- 提交请求重试产生两次Attempt结算；幂等键和状态锁。
- 教练从隐藏答案字段或评分点泄题。
- 主观题AI建议直接写正式成绩。

### 验收

断网后草稿可恢复；多标签冲突有提示；提交只发生一次；考试禁用教练无法通过直接调用绕过；历史结果绑定当时题目版本。

## 7. 任务卡B06：侧边栏分支对话（D31—D35，3人日）

### 执行步骤

1. 用户选中文字时记录source_turn_id、Unicode code point偏移、选中文本和必要前后句。
2. 服务端验证选区确实属于该turn，防止伪造其他会话内容。
3. Branch拥有独立session_id、summary和上下文预算。
4. 分支默认只读取选区、来源turn、当前Evidence和局部摘要。
5. 关闭分支不影响主会话；删除分支按会话规则处理。
6. Merge前展示将带回的结构化内容，由用户确认。
7. Merge只允许`question`、`confirmed_note`、`unresolved_issue`，写入主线系统消息并记录来源branch_id。

### 易错点

- JavaScript UTF-16偏移与后端Unicode偏移不一致。
- 分支自动继承全部主对话导致上下文浪费。
- 分支中的错误猜测被自动写入长期记忆。
- Merge重复点击写入多次；使用幂等键。
- 删除主turn后分支失去可解释来源；采用受控软删除和关系检查。

## 8. 任务卡B07：学习事件、错题与复习（D34—D40，4人日）

### 事件规则

只接收白名单事件；服务端补充actor和course，不能信任客户端传入的学生ID。事件包含event_id、occurred_at、received_at、object_id和最小payload。

### 复习流程

1. 从正式作答、练习状态和教师确认产生候选薄弱证据。
2. 同一知识点聚合时保留来源，不把次数简单相加。
3. 首期采用可解释调度规则：错误后1天、3天、7天复习；正确表现逐步延长。
4. 复习任务包含原因、关联题目和完成条件。
5. 新表现更新下一次到期时间，但保留历史任务。

### 易错点

- 页面点击都上传，形成大量无用数据。
- 客户端可伪造分数或学生ID。
- 一次失误立即标为稳定薄弱点。
- 删除题目后错题记录无法解释。
- 时区导致复习任务提前或延后一天。

## 9. 任务卡B08：L0—L3记忆与上下文压缩（D36—D40，5人日）

### 分层规则

- L0：原始对话、作答和任务事实，仅按需复核。
- L1：带来源的原子事实或候选困难。
- L2：某章节/场景的阶段总结和未解决问题。
- L3：多次证据支持且经确认的稳定偏好或学习模式。

### 写入步骤

1. turn或attempt完成后产生候选，不在流式中途写。
2. 候选必须含evidence_ids、confidence、course_id、type和valid_at。
3. 规则去重后再模型合并；冲突创建新版本，不覆盖旧记录。
4. 低置信度停留L1候选；多来源或用户确认后才能升层。
5. stale默认隐藏但保留审计；合法删除执行物理删除或不可逆匿名化。

### 渐进加载

每轮先读取overview，包括各层数量、主题和更新时间；根据当前知识点最多展开少量条目。上下文预算依次保证课程规则、当前任务、教材Evidence、近期对话，再分配记忆。

### 自动摘要

达到turn或token阈值时生成结构化摘要：学习目标、已确认结论、未解决问题、最近学生答案、已用提示、引用和下一步。摘要必须保留否定词、条件和不确定性；摘要版本可回溯原turn。

### 易错点

- 任何聊天内容都写长期记忆。
- 把“学生问过”误写成“学生不会”。
- 摘要把“不是”遗漏，改变含义。
- L3加载过多，旧画像压制当前表现。
- stale等同删除，用户删除请求未真正执行。
- 记忆跨课程共享导致不同课程评价混用。

## 10. 任务卡B09：画像、统计与教师视图（D38—D45，5人日）

### 掌握状态

首期只使用可解释规则，状态为`evidence_insufficient`、`learning`、`needs_review`、`mastered`。每项保存confidence、evidence_count、last_evidence_at和algorithm_version。

### 教师统计

默认提供班级聚合：章节完成、测验分布、常见错题、知识点状态和资料使用。下钻到个人时只展示教学必要数据，不默认展示私密问答全文。统计页面说明口径和更新时间。

### 易错点

- 一次高分直接标为掌握。
- 分母变化却不显示样本数。
- 缺失事件被当成未学习。
- 排名制造不必要标签化。
- 教师导出包含学号、邮箱和完整对话。
- 算法调整后历史画像无版本，无法解释变化。

## 11. 任务卡B10：E2E、试用和发布支持（D41—D50，5人日）

### E2E矩阵

覆盖首次登录、课程加入、教材阅读、普通问答、无证据拒答、引用跳转、教学状态机、练习教练、正式测验禁用AI、分支追问、复习、记忆纠正、教师统计和退出。

### 异常矩阵

覆盖API 401/403/409/422/429/503、SSE断开、模型超时、解析处理中、引用失效、对象地址过期、弱网、刷新、多标签和重复提交。

### 试用执行

1. 用固定教师脚本建立课程。
2. 用测试学生完成基准任务并记录预期结果。
3. 真实试用前展示数据采集说明。
4. 反馈必须记录角色、环境、复现步骤、期望、实际、截图和request_id。
5. P0立即停止相关功能；P1当日处理；P2进入下个迭代；P3记录优化。

### 心理健康边界

识别自伤、他伤、危机或医疗诊断意图时停止普通教学流程，显示平台边界和学校/当地人工求助渠道。不能只输出泛化免责声明，也不能让课程AI尝试诊断。

## 12. B向A的交接模板

B提交消费问题必须包含接口路径、OpenAPI版本、request_id、用户角色、课程ID、请求样例、预期、实际、发生频率和是否可稳定复现。不能只给页面截图或说“接口不好用”。

## 13. B的最终检查

- 学生所有核心流程均有加载、空、无权、失败和重试状态。
- AI流程可暂停、恢复、退出且不会无限循环。
- 正式测验AI策略服务端生效。
- 分支默认隔离，Merge需要确认且幂等。
- 记忆有来源、置信度、版本、stale、纠正和删除。
- 画像显示证据不足，不输出人格或心理诊断标签。
- 弱网、刷新、多标签和重复提交测试通过。
- 恢复备份后完整业务冒烟通过。
