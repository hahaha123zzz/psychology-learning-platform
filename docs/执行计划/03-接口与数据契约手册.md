# 接口与数据契约手册

## 1. 契约管理规则

1. FastAPI/Pydantic模型是HTTP契约唯一来源，导出`contracts/openapi.json`。
2. Web通过生成器产生TypeScript客户端；生成目录禁止手改。
3. 跨模块内部事件以本文为源，落地为Pydantic事件模型。
4. 删除字段、改变含义、收窄枚举或改变可空性属于破坏性变更，必须升级API或事件版本。
5. 新增可选字段通常兼容；新增必填字段必须有迁移期和默认处理。
6. 每个接口至少提供成功、未登录、无权、校验失败和业务冲突样例。

## 2. 通用类型

### 2.1 ID与时间

- `id`：26位ULID字符串。
- `version`：正整数乐观锁版本。
- 时间：UTC ISO 8601，例如`2026-09-16T08:00:00Z`。
- 日期：`YYYY-MM-DD`，复习日期按用户时区解释。

### 2.2 成功响应

```json
{"data":{},"meta":{"request_id":"01K...","server_time":"2026-09-16T08:00:00Z"}}
```

列表`meta`增加`next_cursor`和`has_more`。禁止有的接口把数据放`result`、有的放`items`而没有统一规则。

### 2.3 错误响应

```json
{
  "error": {
    "code": "RESOURCE_VERSION_CONFLICT",
    "message": "资料已被其他人修改，请刷新后重试",
    "details": {"expected_version": 3, "actual_version": 4},
    "retryable": false
  },
  "request_id": "01K..."
}
```

前端根据`code`处理，不根据中文message做逻辑判断。

## 3. 身份与课程契约

### POST `/api/v1/auth/login`

请求：`email`、`password`。成功设置HttpOnly Cookie，响应返回`user`、`platform_roles`和`session_expires_at`。连续失败按账号与IP组合限流。错误：`INVALID_CREDENTIALS`统一，不区分账号不存在或密码错误。

### GET `/api/v1/me`

响应字段：`id`、`display_name`、`platform_roles`、`course_memberships[{course_id, role, status}]`。不返回密码哈希、刷新令牌和内部权限表达式。

### POST `/api/v1/courses`

权限：教师或管理员授权角色。请求：`title` 1—100字符、`term`、`description?`、`timezone`。响应201 Course。幂等键相同且body相同返回原结果；相同键body不同返回409。

### PATCH `/api/v1/courses/{course_id}`

请求必须带`version`和要修改字段。课程标题修改后`version+1`。无权资源返回404；版本冲突409。

### POST `/api/v1/courses/{course_id}/members`

请求：`user_id`、`role`。不能添加停用账号；不能重复有效成员。角色改变使用专门PATCH并审计。

## 4. 教材与解析契约

### POST `/api/v1/courses/{course_id}/materials`

Multipart字段：`file`、`title`、`material_type`、`visibility`。Header：`Idempotency-Key`。支持PDF/DOCX/PPTX；大小上限配置化。响应：

```json
{
  "data": {
    "material_id":"01K...",
    "version_id":"01K...",
    "status":"uploaded",
    "sha256":"...",
    "size_bytes":123456
  }
}
```

错误：`FILE_TOO_LARGE`、`UNSUPPORTED_MEDIA_TYPE`、`FILE_SIGNATURE_MISMATCH`、`COURSE_STORAGE_QUOTA_EXCEEDED`。

### POST `/api/v1/material-versions/{version_id}/parse`

权限：课程教师。前置状态`uploaded`或可重试`failed`。响应202：`job_id`、`status=queued`。同一版本同时只能有一个活动解析任务。

### GET `/api/v1/jobs/{job_id}`

响应：`kind`、`status`、`progress` 0—100、`stage`、`started_at`、`finished_at`、`error?`、`retryable`。状态为`queued/running/succeeded/failed/cancelled`。进度不得倒退。

### GET `/api/v1/material-versions/{version_id}/outline`

响应章节节点：`id`、`title`、`level`、`parent_id`、`start_page`、`end_page`、`review_status`、`object_count`。返回稳定ID，不让前端以数组序号当ID。

### PATCH `/api/v1/knowledge-objects/{object_id}`

请求：`version`、可修改字段、`reason`。只允许教师修正标题、层级、阅读顺序、正文规范化、图注关联和review_status；原始解析内容不可覆盖。

### POST `/api/v1/material-versions/{version_id}/publish`

发布检查：解析成功、无阻塞质量错误、章节不为空、文件授权状态有效。响应包含`published_at`和`index_job_id`。发布教材不代表索引立即ready。

## 5. 检索与证据契约

### POST `/api/v1/knowledge/search`

调用者：B后端或教师调试页；学生前端不得直接指定任意课程范围。

请求：

```json
{
  "course_id":"01K...",
  "query":"自变量和因变量有什么区别？",
  "chapter_scope":["01K_CHAPTER"],
  "material_version_ids":[],
  "object_types":["paragraph","definition","figure","table"],
  "top_k":8,
  "include_neighbors":true,
  "purpose":"course_qa"
}
```

响应每项EvidenceCandidate：`evidence_id`、`material_id`、`material_version_id`、`title`、`chapter_path`、`physical_page`、`printed_page?`、`anchor`、`bbox?`、`object_type`、`text`、`score`、`retrieval_sources`、`review_status`。响应顶层增加`retrieval_version`、`query_rewrite?`和`warnings`。

规则：`score`仅供系统排序，不向普通学生展示；权限过滤在检索前完成；`material_version_ids`为空表示课程当前已发布版本，不表示全平台资料。

### GET `/api/v1/evidence/{evidence_id}`

每次读取重新校验用户和课程权限。响应：原文、来源、版本、页码、bbox、图表对象、短期preview_url和expires_at。资料取消发布或成员移除后返回404。

### Evidence Package内部模型

```json
{
  "package_id":"01K...",
  "course_id":"01K...",
  "query":"...",
  "retrieval_version":"hybrid-v1",
  "items":[{"evidence_id":"01K...","text":"...","relations":[],"support_level":"candidate"}],
  "context_budget_chars":12000,
  "created_at":"..."
}
```

`support_level`在生成前为candidate，答案校验后可为supported、partial、conflict或not_found。

## 6. 题库与测验契约

### POST `/api/v1/courses/{course_id}/questions`

请求包括`type`、`stem`、`options?`、`answer`、`rubric?`、`explanation`、`difficulty`、`knowledge_point_ids`、`evidence_ids`。创建后状态draft。单选必须恰有一个正确选项；主观题必须有rubric。

### POST `/api/v1/courses/{course_id}/question-generation-jobs`

请求：`chapter_ids`、`knowledge_point_ids`、`question_types`、`count` 1—50、`difficulty_distribution`、`special_requirements?`。响应202 Job。任务输出只生成draft questions。

### POST `/api/v1/questions/{question_id}/review`

请求：`action=approve|reject|request_changes`、`version`、`comment`。reject和request_changes必须有comment。审核动作写AuditLog。

### GET `/api/v1/assessments/{assessment_id}`

学生响应绝不包含答案、解析、rubric和内部Evidence全文。返回`ai_policy=disabled|direction_only|full_after_submit`、开放时间和题目展示字段。

### PUT `/api/v1/attempts/{attempt_id}/answers/{question_id}`

请求：`answer_version`、`response`、`client_saved_at`。成功返回新`answer_version`和`server_saved_at`。版本冲突409，响应当前版本摘要供用户选择。

### POST `/api/v1/attempts/{attempt_id}/submit`

幂等。响应`submitted_at`、`grading_status`和允许立即展示的结果。不得因客户端重复点击重复评分或重复产生事件。

## 7. AI会话与教学契约

### POST `/api/v1/chat/sessions`

请求：`course_id`、`mode=course_qa|tutor|question_coach|review`、`chapter_id?`、`question_version_id?`。服务端验证mode所需上下文。

### POST `/api/v1/chat/sessions/{session_id}/turns`

请求：`content` 1—4000字符、`client_turn_id`、`selected_evidence_ids?`。响应`text/event-stream`。

SSE事件：

- `state`：教学状态或检索阶段。
- `delta`：增量文本，带sequence。
- `citation`：evidence_id和展示标签。
- `action`：`wait_for_student`、`show_example`等前端动作。
- `usage`：token和模型用途；普通学生可不展示。
- `done`：turn_id、finish_reason、saved=true/false。
- `error`：code、retryable、request_id。

客户端只在收到done且saved=true后认为正式完成。

### POST `/api/v1/learning-sessions/{id}/responses`

请求包含`state_version`和学生回答。服务端先验证当前状态是否允许response，再评价并转移。旧version返回409，不重复调用模型。

### POST `/api/v1/learning-sessions/{id}/actions`

允许`request_hint`、`request_example`、`open_material`、`pause`、`resume`、`finish`。动作不在当前状态允许表时返回`ILLEGAL_TUTOR_ACTION`。

## 8. 分支与题目教练契约

### POST `/api/v1/questions/{question_id}/coach-sessions`

请求：`question_version_id`、`attempt_id?`、`current_answer?`。服务端从Assessment读取AI策略，不能相信客户端声明“练习模式”。响应包含`allowed_actions`和`hints_used`，不包含隐藏答案。

### POST `/api/v1/chat/sessions/{id}/branches`

请求：`source_turn_id`、`selected_text`、`selection_start`、`selection_end`、`context_before?`、`context_after?`。后端验证选区文本匹配。

### POST `/api/v1/branches/{branch_id}/merge`

请求：`merge_id`、`type`、`content`、`confirmed=true`。相同merge_id幂等。响应主会话新生成的system note id。

## 9. 记忆、画像和删除契约

### MemoryEntry字段

`id`、`student_id`、`course_id`、`layer`、`type`、`content`、`evidence_ids`、`confidence`、`status=candidate|active|stale|superseded|deletion_pending`、`valid_from`、`last_verified_at`、`source_version`、`supersedes_id?`、`important`、`created_at`。

### GET `/api/v1/me/courses/{course_id}/memory/overview`

只返回分层数量、主题、最近更新时间和待确认数量，用于渐进加载。

### POST `/api/v1/memory/entries/{id}/correct`

请求：`content`、`reason`、`version`。创建新条目并把旧条目标为superseded，不原地覆盖。

### DELETE `/api/v1/memory/entries/{id}`

响应202表示进入删除工作流。平台需明确哪些数据物理删除、哪些因成绩或审计义务保留匿名记录。`important`不能阻止合法删除。

### MasteryState字段

`knowledge_point_id`、`level`、`confidence`、`evidence_count`、`last_evidence_at`、`algorithm_version`、`reasons[]`。数据不足必须返回`evidence_insufficient`，不能省略后由前端猜测。

## 10. 学习事件契约

事件白名单：`material.opened.v1`、`chapter.completed.v1`、`citation.opened.v1`、`attempt.started.v1`、`attempt.submitted.v1`、`hint.requested.v1`、`tutor.step.completed.v1`、`review.completed.v1`。

客户端事件请求只提供`event_id`、`event_type`、`course_id`、`object_id`、`occurred_at`和白名单payload；actor从会话获得。服务端保存received_at并按event_id去重。

## 11. 内部Outbox事件

统一Envelope：

```json
{
  "event_id":"01K...",
  "event_type":"knowledge.index.ready.v1",
  "event_version":1,
  "occurred_at":"...",
  "producer":"knowledge",
  "trace_id":"...",
  "payload":{}
}
```

消费者保存已处理event_id。处理业务和记录消费结果在同一事务；失败指数退避，超过上限进入dead_letter并告警。

关键事件：`material.version.published.v1`、`knowledge.index.ready.v1`、`question.version.published.v1`、`assessment.published.v1`、`attempt.submitted.v1`、`answer.graded.v1`、`tutor.turn.completed.v1`和`memory.entry.changed.v1`。

## 12. 契约测试清单

- OpenAPI无未说明的破坏性差异。
- 每个路径的401/403/404语义一致。
- ULID、时间、枚举和可空字段前后端一致。
- 幂等写接口同键同body返回同结果，同键异body返回409。
- 版本冲突不静默覆盖。
- 学生响应不含答案、rubric、内部Prompt和无权Evidence。
- SSE事件顺序、sequence、done和error可被断线重放策略正确处理。
- 事件消费者重复处理不产生重复业务结果。
