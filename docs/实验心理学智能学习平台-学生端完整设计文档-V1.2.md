# 2. 产品目标

平台不是一个面向实验心理学的 ChatGPT 外壳。

学生端的核心目标是：

```text
让学生知道现在学什么
→ 有教材依据地理解
→ 通过练习和实验产生学习证据
→ 发现误区
→ 得到恰当提示和补救
→ 在合适时间复习
→ 看懂自己的成长状态
→ 获得下一步任务
```

学生端完整学习闭环：

```text
Learning
→ Practice
→ Learning Evidence
→ Student State
→ Review / Remediation
→ Growth
→ Next Task
```

平台中的 AI 是“教学机制”，不是产品视觉中心。

# 3. 设计原则

## 3.1 教材优先

课程事实优先来自：

```text
AuthoritativeTextbook
    >
Teacher-approved CourseSupplementaryResource
    >
Published TeachingAsset explanatory content
```

外部知识不能无标识地混入课程事实回答。

## 3.2 证据优先

对于课程事实类回答：

```text
先检索
→ 形成 EvidencePackage
→ 再回答
→ Claim / Evidence 校验
→ 展示 Citation
```

证据不足时允许：

```text
补检索
降级回答
明确不确定
拒绝强断言
```

## 3.3 教学优先

AI 的目标不是“把答案一次性告诉学生”，而是：

```text
诊断
→ 解释
→ 提示
→ 等待
→ 反馈
→ 微练习
→ 迁移
```

但不能为了“苏格拉底式教学”机械反问。策略必须由当前任务、学生状态和课程政策决定。

## 3.4 学生状态必须可解释

不将一次答错变成“能力差”等稳定标签。

不默认向学生展示：
- 黑盒 AI 置信度；
- 风险分；
- 难以解释的掌握概率。

优先显示：

```text
已比较稳定
正在学习
需要加强
待复习
最近容易混淆
```

并提供证据来源。

## 3.5 正式测评与普通教学隔离

普通 Tutor：
- 可以解释；
- 可以提示；
- 可以生成临时 micro-check。

正式 Assessment：
- 必须遵守独立策略；
- 不得被 Tutor 泄露答案；
- AI 临时题不得自动进入正式题库；
- 正式评分遵守机构和发布策略。

## 3.6 生成式 UI 不等于生成任意前端代码

LLM/Workflow 只能产生：

```text
结构化 Block Schema
```

前端从白名单 `Block Registry` 渲染。

不得：
- 让模型任意输出 React；
- 让模型任意执行 HTML/JS；
- 让未知 Block 直接导致崩溃。

## 3.7 同一学生状态，同一学习任务

所有学生页面围绕统一的：

```text
CurrentLearningTask
Student State
Review State
Learning Evidence
```

不能每个页面各自维护一套“当前任务”和“掌握度”。

# 5. Student Home

## 5.1 核心目标

学生进入系统后 5 秒内回答三个问题：

```text
我现在在学什么？
我现在应该做什么？
我最近哪里需要加强？
```

## 5.2 页面内容

第一屏只保留：

```text
Current Learning Task
Next Action（最多 1–2 个）
Attention Item（最多 1 个）
```

示意：

```text
实验心理学

继续学习
第 3 章 · 选择性注意
[继续学习]

需要复习
3 个知识点
[开始复习]

章节练习
第 3 章
[开始练习]
```

## 5.3 不应该出现

- 全局 ChatGPT 输入框；
- 大量图表；
- 复杂排行榜；
- 夸张的“掌握度 83.7%”；
- AI 风险分；
- 无法解释的推荐。

# 6. “学习”Workspace：双模式、同一 Tutor Core

[V1后讨论][讨论确认]

学生学习有两个主要模式：

```text
学习
├─ AI 引导学习
└─ 教材伴学 Reading Studio
```

两者不是两个独立产品，底层共享：

```text
Tutor Runtime
Student State
Teaching Policy
Presentation Policy
Evidence System
Question System
Review State
Learning Memory
CurrentLearningTask
```

# 7. 模式 A：AI 引导学习

适用场景：

- 学生直接提出学习目标；
- 系统给出 Current Learning Task；
- 学生不知道从哪里开始；
- 学生发生误区；
- 错题后的概念修复；
- 到期复习；
- 知识迁移练习。

典型链路：

```text
Learning Goal / CurrentLearningTask
            ↓
TutorContext
            ↓
必要的快速诊断
            ↓
Strategy Router
            ↓
解释 / 示例 / 提示 / 微练习
            ↓
Learning Evidence
            ↓
Student State
            ↓
继续 / 补救 / 迁移 / 总结 / 完成
```

AI 不应该每次都重新规划整门课程，只规划当前学习 Episode。

---

# 8. 模式 B：Reading Studio 教材伴学

## 8.1 目标

Reading Studio 让“教材”成为学习主体，“AI”成为上下文助手。

桌面建议：

```text
┌──────────────┬────────────────────────────┬──────────────────┐
│ 章节导航      │        Textbook Reader     │ Tutor / Context  │
│              │                            │                  │
│ Chapter      │ 正文 / 图 / 表 / 高亮       │ 解释             │
│ Section      │                            │ Evidence         │
│ Objects      │                            │ 快速动作          │
└──────────────┴────────────────────────────┴──────────────────┘
```

移动端：

```text
教材正文全宽
Tutor / Evidence / Branch
→ Drawer / Bottom Sheet
```

## 8.2 选区与对象操作

学生可针对：

```text
文本
图片
表格
公式
教材局部对象
```

执行：

```text
解释这里
简单一点
举个例子
这里为什么
和 XXX 比较
针对这里练习
加入复习
查看教材依据
```

## 8.3 SelectionContext

统一上下文概念：

```text
SelectionContext
├ course_id
├ material_version_id
├ chapter_id
├ section_id
├ object_id
├ page_no
├ bbox / text_range
├ selected_text
└ selection_type
```

原则：

- 必须绑定 `material_version_id`；
- 对 Figure/Table 优先传 `object_id`；
- 不能只把“第 34 页这张图”当普通字符串扔给模型。

## 8.4 双模式互通

AI 引导学习：

```text
Tutor 引用教材
→ 打开 Reading Studio
→ 高亮原文
→ 学生选中局部
→ 继续追问
```

教材伴学：

```text
选中内容
→ “针对这里练习”
→ Practice Session
```

因此不建立第二套独立“教材 AI”。

# 10. ZIP Tutor Engine：最终借鉴方案

## 10.1 ZIP 的角色

ZIP 不替代现有后端。

它的价值集中在：

> **微观教学循环。**

最终原则：

```text
ZIP 负责“怎么教”
V1 平台负责：
- 教什么
- 依据是什么
- 学生状态是什么
- 什么是正式测评
- 什么可以发布
- 什么需要审计
```

## 10.2 A 类：优先迁移/改造

### Conversation Router

建议收敛为少量课堂 Intent：

```text
QA
LEARN
PRACTICE_HELP
REVIEW_HELP
```

如果后续证明有必要再扩展。

### Strategy Router

首批：

```text
EXPLAIN
HINT
EXAMPLE
MICRO_CHECK
MISCONCEPTION_REPAIR
COMPARE
TRANSFER
REVIEW
EXPERIMENT_GUIDE
```

明日版本至少：

```text
EXPLAIN
HINT
EXAMPLE
MICRO_CHECK
MISCONCEPTION_REPAIR
```

### Lesson Mini Planner

只负责当前 1–3 步：

```text
解释核心概念
→ 给例子
→ micro-check
```

而不是长期课程计划。

### Question Designer

用于普通学习中的：
- 临时 micro-check；
- 变式题；
- 概念辨析。

不得自动进入正式题库。

### Quality Checker

检查：
- 是否使用了应有 Evidence；
- Citation 是否有效；
- 是否违反 Assessment Policy；
- 输出 Block 是否合法；
- Preference 是否生效；
- 证据不足时是否过度断言。

## 10.3 B 类：结构保留但必须适配

### Student State

ZIP 状态不能成为第二套真相源。

统一映射到现有：

```text
Knowledge / Mastery State
Misconception State
Review State
WrongAnswerTrace
HintDependencyState
PresentationPreference
CurrentLearningTask
```

### Memory

ZIP Memory 只能借思想。

平台 Memory 与 Student Model 必须分开：

```text
Memory
= 对后续学习有用的历史上下文

Student Model
= 对学习状态的可解释聚合
```

Memory 不能直接等于“学生能力画像”。

### Evidence

必须拆成：

```text
ContentEvidence
LearningEvidence
```

详见后文。

## 10.4 C 类：不直接搬

### ZIP Retriever

不用 ZIP 的 placeholder Retriever 替换已有教材 RAG。

### ZIP Response Generator

改造为：

```text
Teaching Composer
→ Structured LearningResponse
```

### ZIP 整体后端

禁止整体替换现有：
- Auth；
- Course；
- RAG；
- Review；
- Assessment；
- Memory；
- Release；
- Audit。

# 11. Teaching Policy 与 Presentation Policy

两者职责必须区分。

## 11.1 Teaching Policy

回答：

> “现在应该怎么教？”

例如：

```text
先解释
先提示
先诊断
给 worked example
做 micro-check
进入 misconception repair
结束当前任务
```

## 11.2 Presentation Policy

回答：

> “选定的内容应该怎么呈现？”

例如：

```text
简洁 / 详细
概念优先 / 例子优先
主动提示多少
是否先给核心结论
```

优先级：

```text
System Policy
    >
Assessment Policy
    >
Teacher / Course Policy
    >
Current Teaching State
    >
Student Preference
    >
Agent Default
```

学生偏好不能覆盖考试策略和系统安全规则。

# 12. PresentationPreference

[甲方硬需求][V1后讨论]

## 12.1 初始字段

```text
response_length
  - CONCISE
  - BALANCED
  - DETAILED

explanation_depth
  - CORE_FIRST
  - STANDARD
  - DEEPER

example_order
  - EXAMPLE_FIRST
  - CONCEPT_FIRST
  - ADAPTIVE

support_proactiveness
```

## 12.2 偏好来源

```text
EXPLICIT
OBSERVED_CANDIDATE
CONFIRMED
TEACHER_CONSTRAINED
```

## 12.3 禁止“偷偷改”

一次行为不能形成稳定偏好。

例如学生说：

> “这次简单一点。”

系统应优先理解为：

```text
仅本次
```

如果长期反复发生，可提示：

```text
检测到你最近经常希望回答更简洁：

[仅本次]
[以后默认]
[不用调整]
```

只有用户明确确认，才变成长期设置。

## 12.4 不使用固定学习风格标签

不将学生永久标记成：
- 视觉型；
- 听觉型；
- 某种人格型学习者。

偏好是“呈现偏好”，不是稳定心理测量结论。

# 13. Structured LearningResponse

## 13.1 为什么需要结构化响应

纯 Markdown 的问题：

- 无法稳定渲染交互题；
- Evidence 容易混进正文；
- 无法安全执行 UI 动作；
- Practice/Tutor 难共享组件；
- 不利于版本与测试。

统一输出：

```text
LearningResponse
```

## 13.2 推荐结构

概念示例：

```json
{
  "response_type": "EXPLAIN",
  "blocks": [],
  "evidence": [],
  "actions": [],
  "metadata": {}
}
```

不要求当前仓库必须完全采用这组字段；已有 Contract 优先，缺口再最小扩展。

## 13.3 Response Type

首批：

```text
EXPLAIN
COMPARE
EVIDENCE_EXPLAIN
QUESTION
CORRECTION
FIGURE_EXPLAIN
TABLE_EXPLAIN
WORKED_EXAMPLE
SUMMARY
```

候选：

```text
REVIEW
CASE_REASONING
EXPERIMENT_GUIDE
MISCONCEPTION_REPAIR
```

## 13.4 每轮回答三层

```text
Core Teaching Content
+
Evidence
+
Next Interaction
```

避免把所有内容塞进一个大文本块。

# 15. QuestionBlock 与交互练习

QuestionBlock 必须是真组件，不是把题目写成 Markdown。

首批题型：

```text
SINGLE_CHOICE
MULTI_CHOICE
TRUE_FALSE
SHORT_ANSWER
```

后续：

```text
SORTING
MATCHING
FILL_BLANK
EVIDENCE_CHOICE
SCENARIO_JUDGMENT
```

提交后产生：
- answer event；
- correctness / rubric result；
- hint usage；
- response time（只作学习过程数据，谨慎解释）；
- LearningEvidence。

一次答对不能直接等价为“掌握”。

# 17. Practice Explorer

## 17.1 解决的问题

旧的“一问一答”模式不适合作为主要练习体验。

新的核心：

```text
Practice Explorer
→ Practice Session
→ 多个可交互题目
```

## 17.2 入口

```text
按章节
按知识点
从教材选区发起
从 Growth 薄弱点发起
从 Review 发起
```

## 17.3 Practice Session

一次 Session 可以包含：

```text
5–10 个 PracticeItem
```

每题可有：
- question；
- answer UI；
- feedback；
- hint；
- evidence；
- next action。

## 17.4 题目来源优先级

```text
已审核题库
    >
已发布课程题
    >
学习态临时 Micro-check
```

临时题：
- 仅用于学习；
- 要标识来源；
- 不自动进入正式题库；
- 不直接作为高风险评价依据。

# 18. 正式 Assessment 隔离

[V1继承]

Formal Assessment 必须使用独立 Shell。

在正式测验中：
- Tutor 能否出现由 Assessment Policy 决定；
- 禁止提示答案；
- 保存/恢复遵守测验状态；
- 结果可见策略独立控制；
- 人工评分/AI 评分遵守当前机构政策。

普通 Practice 的“提示/解释”能力不能无条件带入正式测评。

## 19.3 Review Session

统一复用：


## 19.4 复习形式

优先：
- retrieval practice；
- 变式题；
- 概念辨析；
- 迁移；
- delayed check。

不要把复习退化成“重新读一遍答案”。

```text

├ hints_used
```

# 28. ContentEvidence 与 LearningEvidence

这是整个系统必须严格分开的两个概念。

## 28.1 ContentEvidence

回答：

> “这句话为什么成立？”

来源：
- 教材文本；
- Figure；
- Table；
- 已批准补充资料；
- 已发布 TeachingAsset。

用途：
- RAG；
- Citation；
- Claim Verification；
- 教材回跳。

## 28.2 LearningEvidence

回答：

> “为什么系统认为学生正在理解/仍有困难？”

来源：
- 练习回答；
- 提示次数；
- 纠错；
- 迁移题；
- Mini Lab；
- case reasoning；
- 复习表现。

用途：
- Student State；
- Review；
- Growth；
- Teaching Policy。

## 28.3 禁止混淆

教材证据：

```text
“教材第 85 页这样写”
```

不等于：

```text
“学生掌握了”
```

学生答对：

```text
LearningEvidence
```

也不等于：

```text
ContentEvidence
```

# 38. 权限与安全

学生只能访问：
- 自己有权限的课程；
- 已发布资源；
- 自己的学习状态；
- 自己的学习记忆；
- Assessment Policy 允许的数据。

禁止：
- 学生跨课程读取 Memory；
- 通过 Tutor 绕过 Resource Permission；
- 通过 Citation 访问未发布教材版本；
- AI 直接修改正式成绩；
- AI 根据一次行为生成稳定心理/能力标签；
- 未发布 TeachingAsset 出现在学生端；
- 未授权教材上传外部模型。

# 52. 完整学生学习 Episode 示例

以 Stroop Effect 为例：

```text
1. Home
   系统显示：
   “继续学习：Stroop Effect”

2. Learn
   打开教材相关小节。

3. Tutor
   学生问：
   “为什么颜色词会影响颜色命名？”

4. Evidence
   系统检索教材当前版本，找到相关段落/图。

5. Strategy
   选择 EXPLAIN。

6. Response
   先给核心解释，再给教材证据。

7. Reading
   学生点击 Citation，跳到原页并高亮。

8. Selection
   学生选中实验图：
   “解释这个条件。”

9. Figure Help
   系统读取 Figure + Caption + Nearby Text。

10. Micro Check
    Tutor 给一个情境判断题。

11. Student Answer
    学生把 congruent / incongruent 混淆。

12. Misconception Repair
    不直接重复答案，而是：
    对比两个条件
    → 给提示
    → 再给变式题。

13. LearningEvidence
    记录首次错误、提示使用、二次正确。

14. Student State
    标记为：
    “正在学习 / 近期易混淆”
    而不是立即“已掌握”。

15. Review
    系统安排未来复习。

16. Growth
    显示：
    “Stroop 条件辨析：需要加强”
    并可查看证据。

17. Next Task
    进入迁移题或下一知识点。
```

这就是整个学生端设计最核心的“单位行为”。

# 57. 给 Coding Agent 的强制约束

1. 先读当前代码，再决定新建什么。
2. 已有领域对象优先复用。
3. 不新建第二套 Student State。
4. 不新建第二套 Memory。
5. 不用 ZIP Retriever 替代现有 RAG。
6. 不把 Tutor 输出退回纯 Markdown。
7. 结构化 Block 必须有白名单。
8. Unknown Block 必须安全降级。
9. ContentEvidence 与 LearningEvidence 分开。
10. Tutor 不能直接把一次答对写成 mastery。
11. Formal Assessment 遵守独立 Policy。
12. Citation 必须绑定 MaterialVersion。
13. Reader、Tutor、Citation 必须读取同一发布版本。
14. Figure/Table 基础问答优先使用对象、caption、nearby text。
15. 未授权教材不得发往外部模型。
16. AI 不产生稳定人格/能力标签。
17. AI 不自动修改长期 preference。
18. AI 不直接发布 Mini Lab。
19. 新数据库字段必须有前向 migration。
20. 公共 API 变化后更新 OpenAPI/contract。
21. 正常路径之外覆盖权限、幂等、失败恢复与非法状态。
22. 多窗口开发只允许总控集成。
23. Demo 期间优先稳定闭环，不扩无关范围。
24. 所有“已完成”必须有代码与测试/浏览器证据。

# 58. 最终结论

学生端下一阶段不是“再加一个聊天页”，而是将当前已有的教材、RAG、Tutor、题库、复习、成长、Mini Lab 和学生状态能力统一为一个真正的学习系统。

核心结构可以压缩成：

```text
四入口
学习 / 实训 / 成长 / 我的

学习双模式
AI Guided Learning + Reading Studio

一个 Tutor Core
Teaching Policy
+ ZIP 微观教学循环
+ Workflow
+ Tool Registry

一种结构化输出
LearningResponse + Block Registry

两类证据
ContentEvidence + LearningEvidence

一个学习闭环
Learn → Practice → Evidence → State → Review → Growth → Next
```

甲方的 8 项需求都应从这套结构中自然得到，而不是分别开发 8 个互不关联的功能。

短期 V0.9 的任务是：

> **先把上述完整架构中最核心的学生黄金链真实跑通。**

长期 V1.2 的任务是：

> **在不破坏这条主线的前提下，逐步补齐 Student Model、Review、实验心理学工作流和高级多模态能力。**

这份文档作为后续学生端产品、架构、开发和验收的统一设计基线。
